> **문서 요약 (Summary)**: 공공기관 대상 회선·네트워크 구축 사업의 **입찰 준비 프로세스**(사업 발굴 → RFP → 현장 실사)를 실제 동행 사례 2건으로 정리하고(PART 1), 현장 회의에서 등장한 **네트워크·보안 용어 30여 개**를 실무 관점에서 해설(PART 2)한 뒤, 공공망 설계의 대표 레퍼런스인 **국가융합망의 구조를 구조도 2장과 함께** 정리(PART 3)한 문서입니다.

# PART 1. 공공 입찰 사업 준비 프로세스 (사내 프로세스)

## 1. 프로세스 목적 (Purpose)

- 경쟁사가 장기 수주해 온 사업, 또는 접근이 어려웠던 신규 고객의 사업을 **입찰 단계 이전부터 관리**하여 수주 가능성을 높이는 것이 목적입니다.
- 핵심 원리: **RFP(제안요청서, Request For Proposal)가 공고되기 전에 이미 승부의 상당 부분이 결정됩니다.** 고객이 원하는 망 구조·투자 범위를 먼저 파악하고, 우리에게 유리한 조건이 RFP에 반영되도록 사전 영업을 하는 것이 공공 영업의 본질입니다.

## 2. 사전 준비 및 권한 (Prerequisites)

- **RFP/입찰공고서 분석 능력**: 과업 범위, 예산, 평가 기준, 모호한 요구사항 식별
- **질문지(질의서) 작성**: 방문 전 반드시 사전 전달 — 고객이 답을 준비할 수 있고, 우리가 무엇을 원하는지 명확해짐
- **협력 체계**: 본사 컨설팅팀, BP사(Business Partner, 장비 공급·구축 협력사), 현장 유지보수업체와의 소통 채널
- **조달 제도 이해**: 나라장터(KONEPS) 사전규격공개 → 의견등록(이의신청) → 본공고 → 제안평가 흐름

## 3. 업무 절차 (Step-by-Step Workflow)

### 사례 ① A부처 — "공고 없던 사업을 공고로 만들기" (수의/독점 구도 → 경쟁입찰 유도)

| 단계 | 시기 | 담당 | 내용 |
|---|---|---|---|
| 1. 사업 발굴 | 4월~ | 영업 | 기존에 입찰공고 없이 특정 통신사가 계속 수주하던 사업 식별. **경쟁입찰(공고)로 전환되도록** 고객·이해관계자 대상 사전 활동 시작 |
| 2. 현장 정보 수집 | 상시 | 영업 | 고객사에 상주하는 **유지보수업체** 면담 — 현장을 가장 잘 아는 사람에게서 망 현황·불편사항 파악 |
| 3. RFP 형성 지원 | 4~9월 | 영업+고객 | RFP가 나오려면 "이 사업에 어떤 투자가 더 필요한지" 고객 내부 협의가 선행되어야 함. 고객이 원하는 형태를 파악해 RFP 구체화를 지원 (약 5개월 소요) |
| 4. 내부 전략 회의 | 공고 임박 | 영업+컨설팅팀+BP사 | 고객 미팅 전 사전 회의. **영업이 파악한 '망 구조·고객이 원하는 형태'를 컨설팅팀에 전달**하고, 제안 전략 방향을 미리 공유 |
| 5. 고객사 방문 실사 | 공고 임박 | 영업(+기술) | 질문지 사전 전달 → 유지보수업체 인터뷰 → **장비실 실사** |
| 6. 원격지(지사) 실사 | 다음 단계 | 영업+기술 | 본사 외 **지사 장비·망 구조 확인**. 특히 **최근 장애가 발생했던 지역** 우선 방문 (장애 포인트 = 제안 포인트) |

**5단계 현장 실사에서 반드시 파악할 것 (체크리스트)**

- [ ] **과업의 범위** — 예산 규모 추정의 기초
- [ ] **현재 망 구성도** — 어떤 장비가 어디에, 어떻게 연결되어 있는가
- [ ] **고객의 불편사항(Pain Point)** — 현 망에서 불편한 점, **장애가 자주 나는 포인트**
- [ ] **내년 구상 중인 망 구조** — 고객의 투자 방향 = 제안서의 핵심
- [ ] **교체가 필요한 장비** — 노후·단종(EOS) 장비 목록
- [ ] **대고객 투자장비 이력** — 기존 사업자(타 통신사)가 어떤 장비를 얼마나 무상 지원했는가 → 우리의 투자 수준 산정 기준

### 사례 ② B공사 — "접근이 어려운 고객 뚫기" (신규 접점 확보형)

| 단계 | 담당 | 내용 |
|---|---|---|
| 1. 접점 확보 | 영업 | 기존 접점이 없던 고객에게 **먼저 연락하여 방문 요청** — 공공기관은 공정성 차원에서 잠재 입찰자의 질의·현장설명 요청에 협조하는 경우가 많음 |
| 2. RFP 분석 | 영업+기술 | RFP 정독 후 **모호한 내용, 우리가 모르는 내역**을 질문 리스트로 정리 |
| 3. 1차 방문(질의) | 영업 | 질의 진행 + **다음 약속 확보** (전문가 동반 장비실 실사 목적) |
| 4. 2차 방문(실사) | 영업+BP사 | BP사 전문가와 함께 본사 장비실 실사, **장비 세부 질의** |
| 5. 확장 실사 요청 | 영업 | 타 지역 장비실 방문 협조 요청 → 지속 협조 확보 |

### ⚠️ 이번에 생략됐지만 원칙적으로 챙겨야 하는 것: 사전규격 검토와 이의신청

- 공공 입찰은 본공고 전에 **사전규격공개**(나라장터, 통상 5일 이상)를 거칩니다.
- 이 단계에서 **우리가 참여 가능한 조건인지**(특정사 유리 조항, 과도한 자격 요건, 특정 장비 스펙 지정 등)를 판단하고, 불리하면 **의견등록(이의신청)으로 규격 변경을 요구**해야 합니다.
- 사전규격 단계를 놓치면 본공고 후에는 조건 변경이 사실상 불가능 → **사전규격 모니터링은 루틴 업무로 관리**할 것.

## 4. 유관 부서 및 협업 포인트 (R&R)

| 주체 | 역할 | 협업 포인트 |
|---|---|---|
| **영업팀 (우리)** | 고객 접점, 정보 수집, 사업 총괄 관리 | 고객과 직접 소통할 수 있는 유일한 채널. **파악한 정보(망 구조, 고객 니즈)를 컨설팅팀·BP사에 전달하는 허브** 역할 |
| **본사 컨설팅팀** | 제안 전략, 기술 컨설팅 | 고객 접점이 적으므로 **영업이 전략 방향과 고객 정보를 먼저 전달**해야 제 역할 가능 |
| **BP사** | 장비 공급, 구축·시공 | 공동 영업 가능. **전체 비용 분담 구조를 BP사와의 협의에서 결정** → 지속적 소통으로 사업 진행 관리 (가장 중요한 협력관계) |
| **유지보수업체** | 고객사 상주, 현장 운영 | 현장 정보의 원천. 망 현황·장애 이력·고객 불만을 가장 잘 앎 |

# PART 2. 현장 회의 용어·기술 해설 (기술 개념)

> **읽는 법**: 용어를 5개 그룹으로 묶었습니다. **① 망의 구분 → ② 이중화 → ③ 보안 → ④ 관제·운영 → ⑤ IP 네트워크 기초** 순서로 읽으면 회의 내용이 하나의 그림으로 연결됩니다.

## 그룹 ① 망의 구분 — 전송망, 정보망, 교환망

### 전송망 vs 정보망 vs 교환망

| 구분 | 전송망 (Transport Network) | 정보망 (IP/데이터망) | 교환망 (Switching Network) |
|---|---|---|---|
| **역할** | 트래픽을 **물리적으로 실어 나르는 파이프** | 데이터를 **IP 주소 기준으로 목적지까지 배달** | **전화 호(Call)를 연결**해 주는 망 |
| **계층** | L1 (물리 계층) | L3 (네트워크 계층) | 음성 호 처리 |
| **주요 장비** | 광케이블, MSPP, WDM/OTN 전송장비 | 라우터(Router), 스위치(Switch) | 교환기, Softswitch, IP-PBX |
| **비유** | 고속도로 | 도로 위를 달리며 주소를 찾는 택배차 | 전화 연결해 주는 교환원 |

- **핵심**: 하나의 회선 서비스도 실제로는 "전송망(물리 경로) 위에 정보망(IP)이 올라가는" 2층 구조입니다. 고객 장비실에서 보는 장비도 **전송장비인지, IP 장비(라우터)인지** 구분해서 봐야 합니다.
- 전화는 과거 교환망(PSTN)으로 처리했지만, 현재는 IP 망 위의 인터넷전화(IPT)로 통합되는 추세입니다. → 그룹 ⑤ IPT 참고

### 라우터 (Router)의 역할

- **정의**: 서로 다른 네트워크(IP 대역) 간에 **최적 경로를 찾아 패킷을 전달(라우팅)**하는 L3 장비.
- 실무 관점: 고객사 본사–지사–인터넷–행정망 등 **여러 망이 만나는 접점마다 라우터가 존재**합니다. 라우터 위치와 수량이 곧 망 구조도의 뼈대입니다.

### 집선 라우터 (Aggregation Router)

- **정의**: 여러 지사·부서·가입자의 회선을 **한곳에 모아(집선, Aggregation) 상위망으로 올려 주는** 라우터.
- 실무 관점: 지사가 수십 곳인 고객(A부처, B공사 유형)은 지사 회선이 지역 거점의 집선 라우터에 모인 뒤 본사/센터로 올라가는 **계층(Hierarchy) 구조**를 가집니다. 집선 지점은 **트래픽이 몰리고, 장애 시 파급 범위가 큰 포인트**이므로 이중화 대상 1순위입니다.

### COT (Central Office Terminal, 국사측 종단장치)

- **정의**: 전용회선·광전송 서비스에서 **통신사 국사(Central Office) 쪽에 설치되는 회선 종단장치**. 고객사(원격지) 쪽에 설치되는 짝꿍 장비는 **RT (Remote Terminal)**라고 부릅니다.
- **"각 노드에 COT를 단다"는 의미**: 각 지사(노드)마다 회선을 개별적으로 국사에서 종단시킨다는 뜻 → **노드 수만큼 장비·상면·비용이 늘어남**. 반대로 집선 구조로 설계하면 COT 수를 줄일 수 있음. 즉, 이 말이 나오면 **"망 설계 방식과 투자비"에 대한 논의**라고 이해하면 됩니다.

### "1·2행정망" (제1망·제2망) — 국가융합망의 이원화 백본

- 회의에서 나온 "1, 2행정망"은 **국가융합망의 제1망·제2망**을 가리킬 가능성이 높습니다. 정부부처 행정업무 트래픽을 **서로 다른 통신사가 운영하는 두 개의 백본망**에 이중으로 태우는 구성입니다.
- 제1망(주망) 장애·재해 시 제2망(백업망)으로 우회 → 행정업무 연속성 확보. 장비 이중화가 아니라 **사업자 단위 이원화**라는 점이 핵심입니다.
- 상세 구조(사업자, 노드 설계, 양자암호 적용)는 **→ PART 3. 국가융합망** 참고.
- ✍️ *현장마다 부르는 이름이 달라, 정확한 지칭은 선배/고객에게 재확인 필요.*

### 전진배치 (Forward Deployment)

- **정의**: 장비나 기능을 중앙(센터)에 두지 않고 **트래픽이 발생·유입되는 앞단으로 옮겨 배치**하는 설계 방식.
- 예시: ① 보안장비(DDoS 차단 등)를 인터넷 인입 구간 앞단에 전진배치 → 위협이 내부로 들어오기 전에 차단, ② 자주 쓰는 기능·장비를 지사 가까이 전진배치 → 응답속도 개선, 센터 집중 부하 분산.
- 실무 관점: RFP에 "전진배치"가 나오면 **어떤 장비를, 어느 위치(본사/지사/인입점)에 두라는 것인지**가 견적과 직결되므로 반드시 질의로 명확히 해야 합니다.

## 그룹 ② 이중화와 무중단 — 공공망의 생명은 가용성

### Active-Standby vs Active-Active

| 구분 | Active-Standby | Active-Active |
|---|---|---|
| **동작** | 주장비(Active)만 운영, 예비장비(Standby)는 대기하다 장애 시 인계 | 두 장비가 **동시에 트래픽 분담** 처리 |
| **장점** | 구성 단순, 장애 절체 시나리오 명확 | 평시에도 자원 100% 활용, 성능↑ |
| **단점** | Standby 자원이 평시에 놀고 있음 | 구성 복잡, 한쪽 장애 시 남은 쪽이 전체 부하 감당 가능해야 함 |

- 공공기관 RFP에서 "이중화(HA, High Availability) 구성"이 나오면 **어느 방식인지, 절체 시간 요건은 몇 초인지** 확인이 필요합니다.

### VPN 이중화

- **정의**: 본사–지사 연결을 VPN(Virtual Private Network) 터널로 구성하되, **주회선 장애 시 다른 경로의 VPN으로 우회**하도록 하는 구성. 대표 패턴: **주회선 = 전용회선, 백업 = 인터넷 VPN(IPSec)** — 백업 회선 비용을 낮추면서 연속성 확보.
- **"전송망/정보망 각각에 가능한가?"에 대한 답**:
  - **정보망(IP망)**: 가능. VPN 자체가 IP(L3) 기술이므로 정보망 이중화의 표준 수단.
  - **전송망(L1)**: VPN이라는 개념이 적용되지 않음. 전송망의 이중화는 **광케이블 경로 이원화, 전송장비의 링(Ring) 구성** 등 물리적 방식으로 합니다.
  - 즉 "VPN으로 이중화"는 **정보망 레벨의 백업 이야기**이고, 전송망 레벨 이중화는 별도로 설계해야 합니다.

### 무중단 전환 (Seamless Migration)

- **정의**: 서비스를 끊지 않고(또는 수 초 이내 순단만으로) 회선·장비·사업자를 교체하는 것.
- 실무 관점: **사업자가 교체되는 입찰에서 단골 요구사항**. 신규망을 기존망과 **병행 구축 → 검증 → 야간/주말 절체** 방식으로 수행. 제안서에 전환 계획(Migration Plan)의 구체성이 평가 포인트가 됩니다.

### UPS (Uninterruptible Power Supply, 무정전 전원장치)

- **정의**: 정전 시 배터리로 즉시 전원을 이어 주는 장치. 통신장비는 순간 정전에도 리부팅되므로 장비실 필수 설비.
- 실무 관점: 장비실 실사 시 **UPS 유무·용량·배터리 교체 이력**은 기본 확인 항목. (전원 이중화가 안 된 장비실 = 장애 포인트 = 제안 포인트)

## 그룹 ③ 보안 — 공공기관 사업의 최대 관문

### N2SF (National Network Security Framework, 국가 망 보안체계)

- **정의**: 국가정보원이 주관하는 새 보안 프레임워크. 기존의 **일률적인 물리적 망분리** 대신, 업무·정보의 중요도를 **C/S/O 등급으로 분류해 등급별로 차등화된 보안통제**를 적용합니다.
- **왜 중요한가**: AI·클라우드 활용을 위해 획일적 망분리를 완화하는 정책 전환으로, **공공기관 망 구조 재설계(= 우리 사업 기회)의 근거**가 되는 제도입니다. 2025년 가이드라인 발표 후 공공기관 적용이 확산 중입니다.

### C/S/O 등급 (N2SF의 정보 분류)

| 등급 | 의미 | 통제 수준 |
|---|---|---|
| **C (Classified)** | 기밀 정보 | 가장 강한 통제 (물리적 분리 수준) |
| **S (Sensitive)** | 민감 정보 | 중간 수준 통제 |
| **O (Open)** | 공개 정보 | 완화된 통제 (인터넷 연계 허용 폭 큼) |

- 회의에서 "CSO"가 나오면 대부분 이 **C/S/O 등급 분류** 이야기입니다. (문맥에 따라 Chief Security Officer(보안책임자)를 뜻할 수도 있으니 구분할 것)

### 회선 암호화 장비

- **정의**: 본사–지사 등 **회선 구간을 지나는 데이터 전체를 암호화**하는 전용 장비. 회선이 도청·탈취되어도 내용을 볼 수 없게 합니다.
- 실무 관점: 공공기관은 **국정원 검증필 암호모듈(KCMVP, Korea Cryptographic Module Validation Program)** 탑재 장비를 요구하는 것이 일반적. RFP의 암호화 요구사항은 장비 선정 폭을 크게 좁히므로 BP사와 초기에 확인해야 합니다.

### PQC 장비 (Post-Quantum Cryptography, 양자내성암호)

- **정의**: 양자컴퓨터로도 풀기 어려운 새 암호 알고리즘(PQC)을 적용한 (회선)암호화 장비.
- **왜 지금 나오는가**: "지금 암호화된 데이터를 훔쳐 두었다가 나중에 양자컴퓨터로 푼다(Harvest Now, Decrypt Later)"는 위협 때문에, 정부가 **국가 암호체계의 PQC 전환(~2035 로드맵)**을 추진 중이며 공공기관 도입 의무화가 확대되고 있습니다. 국정원은 기존 암호와 PQC를 함께 쓰는 **하이브리드 방식**을 허용했고, KCMVP 인증을 받은 PQC 장비는 아직 소수라 **공급이 병목**입니다.
- 실무 관점: RFP에 PQC가 명시되면 **조달 가능한 인증 장비가 극히 제한적** → 장비 수급·가격을 BP사와 가장 먼저 확인해야 하는 항목입니다.

### 망분리 보조 기술: VDI, 망연계

- **VDI (Virtual Desktop Infrastructure, 가상 데스크톱)**: 실제 PC가 아니라 **서버에 있는 가상 PC 화면만 전송받아 쓰는** 방식. 인터넷용 가상 PC를 따로 두면 물리 PC 2대 없이 **논리적 망분리**가 가능 → 공공기관 인터넷망 분리의 대표 수단.

### SSL 가시성 (SSL/TLS Visibility)

- **정의**: 요즘 웹 트래픽은 대부분 암호화(HTTPS)되어 보안장비가 내용을 검사할 수 없습니다. SSL 가시성 장비는 **암호화 트래픽을 중간에서 복호화 → 보안장비(IPS, 유해차단 등)가 검사 → 재암호화**해 주는 장비입니다.
- **유해차단(유해사이트 차단)과의 관계**: 유해차단은 URL/도메인 기반으로 접속을 막는 기능인데, HTTPS 환경에서는 SSL 가시성 장비가 있어야 **암호화된 트래픽 안의 실제 URL까지 보고 정밀 차단**이 가능합니다. 그래서 두 장비가 세트로 논의됩니다.

### NAC (Network Access Control, 네트워크 접근제어)

- **정의**: **허가된 단말만 사내망에 접속**하도록 통제하는 시스템. 미등록 PC·노트북이 랜선을 꽂아도 망 사용을 차단하고, 백신·패치 등 보안상태를 검사해 미달 단말을 격리합니다.

### TMS (Threat Management System, 위협관리시스템)

- **정의**: 네트워크 트래픽을 실시간 분석해 **해킹 시도·악성코드 등 위협을 탐지**하고 관제 인력에게 알려 주는 시스템. 공공기관 보안관제의 표준 구성요소입니다.

## 그룹 ④ 관제·운영 — 망을 "지켜보는" 체계

| 용어 | 풀네임 | 역할 | 한 줄 구분 |
|---|---|---|---|
| **NMS** | Network Management System | 네트워크 장비의 **구성·성능·장애를 중앙에서 모니터링/관리**하는 소프트웨어 시스템 (SNMP 기반) | "장비와 회선 상태를 보는 **시스템**" |
| **FMS** | Facility Management System | 장비실·국사의 **환경(온습도, 정전, 누수, 화재, 출입)을 감시**하는 시설관리 시스템 | "장비가 놓인 **공간**을 보는 시스템" |
| **NOC** | Network Operations Center | NMS·FMS 등을 모아 놓고 **사람이 24시간 관제하는 조직/센터** | "시스템이 아니라 **관제 조직**" |

- 실무 관점: RFP에서 "NMS 구축", "FMS 연동", "NOC 운영" 요구는 각각 **소프트웨어 구축 / 센서·설비 공사 / 인력 운영** 비용으로, 성격이 완전히 다릅니다. 과업 범위 산정 시 구분해서 봐야 합니다.
- 이 시스템들이 **전송망용인지 정보망용인지**도 확인 포인트: 전송장비 관제(전송 NMS)와 IP 장비 관제(IP NMS)는 보통 별도 시스템입니다.

## 그룹 ⑤ IP 네트워크·회선 기초 용어

### QoS (Quality of Service) — 필요한 경우 vs 불필요한 경우

- **정의**: 회선 대역폭이 부족할 때 **중요 트래픽(음성, 영상회의, 제어신호)을 우선 처리**하도록 우선순위를 매기는 기술.
- **필요한 경우**: 하나의 회선에 음성(IPT)+데이터가 섞여 흐를 때, 지사 회선처럼 대역이 좁을 때, 실시간성 트래픽(영상회의, 관제 영상)이 있을 때.
- **불필요한(덜 중요한) 경우**: 대역폭이 트래픽 대비 충분히 여유로울 때, 전용회선처럼 **대역이 보장**되고 단일 용도로만 쓸 때. → QoS는 "부족할 때 줄 세우는 기술"이므로, 애초에 안 부족하면 필요성이 낮음.
- 실무 관점: 고객이 QoS를 요구하면 **"어떤 트래픽을 보호하고 싶은가"**를 물어보면 됩니다. 그 답이 곧 고객의 핵심 업무입니다.

### NAT (Network Address Translation, 주소 변환)

- **정의**: 내부에서 쓰는 **사설 IP를 외부 통신 시 공인 IP로 바꿔 주는** 기술. 공인 IP 부족 해결 + 내부 주소 은닉(보안) 효과.
- 실무 관점: 기관 간 망 연동 시 **양쪽 사설 IP 대역이 겹치면 NAT로 변환**해서 연결합니다. 연동 구간 설계에서 자주 등장.

### VLAN (Virtual LAN, 가상 랜)

- **정의**: 물리적으로 같은 스위치에 꽂혀 있어도 **논리적으로 별도의 망처럼 분리**하는 기술. (예: 같은 층 스위치에서 업무망 VLAN / 방문자망 VLAN 분리)
- 실무 관점: 부서·용도별 망 분리를 장비 추가 없이 구현하는 기본 수단. 망 구성도의 "논리 구성"을 이해하는 열쇠.

### IPT (IP Telephony)와 전화 회선의 차이

| 구분 | 기존 전화 (PSTN/E1) | IPT (인터넷전화) |
|---|---|---|
| **전달 방식** | 전화 전용 회선·교환망 | 데이터망(IP) 위에 음성을 패킷으로 전송 (VoIP) |
| **필요 장비** | 교환기(PBX), 국선/E1 트렁크 | IP-PBX 또는 인터넷전화 교환 서버, IP 전화기, (품질 보장용 QoS) |
| **특징** | 안정적이나 회선·교환기 비용, 유연성↓ | 데이터망과 통합 운영, 증설 유연, **정전·망 장애 시 전화도 함께 끊김** → UPS·이중화 중요 |

- 실무 관점: 공공기관 사업에서 "전화 회선"이 나오면 **기존 PSTN 유지인지, IPT 전환인지**에 따라 제안 구성이 완전히 달라집니다. (상세: 「PSTN-E1 기술개념」 문서 참고)

### EOS (End of Service/Support, 단종)

- **정의**: 제조사가 장비의 **판매·기술지원·보안패치를 종료**하는 것. EOS 장비는 장애 시 부품 수급이 안 되고 보안 취약점 패치도 불가.
- 실무 관점: 실사에서 확인한 **EOS(임박) 장비 목록은 곧 교체 수요 = 사업 예산의 근거**입니다. "교체가 필요한 장비" 질문의 기술적 표현이 EOS 여부 확인입니다.

# PART 3. 국가융합망 — 공공망 설계의 대표 레퍼런스 (기술 개념)

> **문서 요약 (Summary)**: 국가융합망(K-Convergence Network)은 48개 정부부처·기관이 각자 임차해 쓰던 개별 업무망을 **하나의 국가 백본망으로 통합**한 망으로, 행정안전부 국가정보자원관리원이 운영합니다. **백본망을 사업자 단위로 이원화(제1망·제2망)**하고 국가기간망 최초로 **양자암호통신(QKD)**을 적용한 것이 설계의 핵심입니다.

## 1. 왜 만들었나 (Key Concepts)

- **통합 전**: 각 부처가 본부–지방청–소속기관을 잇기 위해 통신사 회선을 **따로따로 임차** → 중복 투자, 제각각인 보안 수준, 부처별 장애 대응
- **통합 후**: 하나의 백본망 공동 사용 → **중복 회선 제거(예산 절감) + 대역폭 확대 + 재난 시에도 중단 없는 행정 서비스**
- 2021년 6월 개통. 기존 국가정보통신망(K-net)을 대체·통합

## 2. 구성 및 동작 원리 (Architecture & Mechanism)

### 설계 사상: "사업자까지 이원화한 2중 백본"

장비 2대를 두는 이중화가 아니라, **백본망 전체를 서로 다른 통신사가 각각 하나씩 운영**합니다. 광케이블 경로·통신국사·장비가 회사 차원에서 분리되므로, 한 사업자 망 전체가 마비되는 대형 장애(국사 화재, 백본 절단)에도 다른 망으로 살아남습니다. PART 2의 **Active-Standby 이중화를 국가망 스케일로 구현**한 것입니다.

| **제2망 (백업망)** | LG유플러스 — **21개 노드, 14개 권역** (지방합동청사 중심) | **SK브로드밴드** — 정부청사 중심 **21개 노드** |
| **연결 방식** | 백본 이원화 구성 | **그물망(Mesh)** — 노드 간 다중 경로로 우회 선택지 확대 |
| **예산** | 약 806억 원 (1망 520억 / 2망 286억) | 약 830억 원 (1망 481억 / 2망 350억) |

- **이원화 원칙**: 평가 1위 사업자도 두 망을 모두 가질 수 없음 (2차에서 1위 KT는 1망만, 2망은 2위 SK브로드밴드가 수주). 망 운영 독립성을 제도로 보장하는 장치입니다.
- 각 부처·기관은 **접속망(전용회선)으로 가까운 백본 노드에 연결**되며, 1망·2망 양쪽에 물려야 이중화가 완성됩니다.
- 노드 배치 기준이 "지자체 중심(1망) vs 정부청사 중심(2망)"으로 다른 것도 의도된 설계 — 두 망이 같은 위치·같은 경로에 몰리지 않게 합니다.

### 백본 노드 내부 — PART 2 용어들이 만나는 자리

![그림 2. 백본 노드 내부 구성](그림2-백본노드-구성도.png)
*(Confluence 업로드 시 첨부파일 `그림2-백본노드-구성도.png` 삽입)*

한 노드 안에 **COT(회선 종단) → 집선/백본 라우터(정보망 L3) → 회선 암호화 장비 → 전송장비(전송망 L1)**가 차례로 놓이고, UPS·FMS가 이를 받치며, NMS·NOC가 원격 관제합니다. "각 노드에 COT를 단다", "집선 라우터", "회선 암호화 장비" 같은 회의 발언이 전부 이 노드 구성(= 노드 수 × 장비 = 투자비) 논의입니다.

### 양자암호 적용 — QKD와 PQC의 역할 분담

- 국가융합망은 **세계 최초로 양자암호통신을 적용한 국가기간망**: 1차 사업에서 **핵심노드 간 전송구간에 QKD(Quantum Key Distribution, 양자키분배)** 적용 (48개 기관 중 33개 우선 적용 후 확대). 암호키를 나르는 양자채널(QC)과 별도의 키채널(Key Channel)을 함께 구축.
- **QKD vs PQC 역할 분담**: QKD는 전용 광케이블 구간이 필요해 **핵심 백본 구간**에, PQC(양자내성암호)는 소프트웨어/장비 적용이 가능해 **일반 구간·단말 구간**에 — 두 기술을 병행하는 것이 공공망의 표준 흐름입니다. (B공사 회의에서 PQC 장비가 나온 배경)

## 3. 실무 적용 사례 (Use Case) — 영업 관점에서 왜 알아야 하나

- **중앙부처 고객(A부처 유형)**: 부처 망의 상당 부분이 이미 융합망 백본 위에 있음 → 제안 시 "이 트래픽이 **융합망 백본을 타는 구간**인지, 기관이 **자체 조달하는 접속망·내부망 구간**인지"를 구분해야 과업 범위와 견적이 정확해짐. 우리가 2차 사업 **제2망 사업자**이므로 융합망 접속 구간에서 자사 인프라 연계를 제안 논리로 활용 가능.
- **공기업 고객(B공사 유형)**: 융합망 의무 대상이 아니어서 자체 전용망을 조달 → 융합망의 "**사업자 이원화 + 노드별 암호화 + Mesh 백본**" 설계가 그대로 제안 벤치마크 레퍼런스가 됨.
