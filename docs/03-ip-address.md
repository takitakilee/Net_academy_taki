# [기술 개념] IP 주소 체계: 공인/사설 IP와 클래스(Class)의 결합

---

## 문서 요약 (Summary)

IP 주소는 **크기(Class A/B/C)** 와 **용도(공인 Public / 사설 Private)** 라는 두 축이 교차하여 운영됩니다. 이 문서는 두 개념이 어떻게 결합되는지와, 사내 네트워크 설계 시 어떤 사설 IP 대역을 선택해야 하는지를 다룹니다.

---

## 핵심 개념 (Key Concepts)

- **공인 IP (Public IP)**
  - 통신사로부터 유상으로 임대받는, 인터넷에서 유일하게 식별되는 주소
  - 회사를 외부 인터넷 세상에 노출시키는 공식 주소
- **사설 IP (Private IP)**
  - **IANA (Internet Assigned Numbers Authority)** 가 각 클래스 대역 안에 지정해 둔 '사설 전용 절대 구역'
  - 누구의 허락도 필요 없이 **무료로 자유롭게** 사용 가능
  - 이 대역이 인터넷 망에 돌아다니면 라우터가 비정상 트래픽으로 간주하고 **즉시 폐기(Drop)**
- **클래스 (Class)**
  - IP 주소를 네트워크 규모에 따라 구분하는 체계 (A: 초대형, B: 중대형, C: 소형)
  - 사설 전용 구역을 제외한 나머지 전 구역이 공인 IP

### 클래스별 공인/사설 대역표

| 클래스 | 전체 대역 (공인 포함) | 사설 IP 전용 구역 | 사설 대역의 대표 사용처 |
|---|---|---|---|
| **A 클래스** | 1.0.0.0 ~ 126.255.255.255 | **10.0.0.0 ~ 10.255.255.255** | 대기업 사내망, 클라우드(AWS, GCP) 가상 서버망 |
| **B 클래스** | 128.0.0.0 ~ 191.255.255.255 | **172.16.0.0 ~ 172.31.255.255** | 중견기업 사내망, Docker 등 컨테이너 가상 네트워크 |
| **C 클래스** | 192.0.0.0 ~ 223.255.255.255 | **192.168.0.0 ~ 192.168.255.255** | 일반 가정(공유기), 소규모 카페, 소기업 |

### 실무 설계에서의 오해와 진실

- **오해**: "직원 50명 소기업(C클래스 규모)이니 내부 사설 IP도 무조건 C클래스 사설 대역(192.168.x.x)만 써야 한다?"
- **진실**: 사설 IP는 허락 없이 무료로 자유롭게 쓰는 번호입니다. 직원 5명인 카페라도 관리자가 공유기 설정을 바꿔 **A클래스 사설 대역(10.0.0.1)** 을 부여해도 아무 문제가 없습니다. 가정용 공유기 제조사들이 기본값을 192.168.x.x로 세팅해 두어 관행으로 굳어진 것뿐입니다.

## 구성 및 동작 원리 (Architecture & Mechanism)

### 대규모 사내망 구축 시나리오 (직원 10,000명 기업)

#### 1단계: 공인 IP 할당 (외부 대표 번호)

- 통신사(KT, SKT 등)에 기업용 전용선을 신청하여 **C클래스 공인 IP 대역 1개** (예: 210.10.10.0/24, 가용 IP 약 250개)를 유상 임대
- 이 주소가 회사의 외부 인터넷 공식 주소

#### 2단계: 사설 IP 설계 (내부 내선 번호)

- 직원 10,000명이므로 C클래스 사설 대역(254대 수용)이나 B클래스 일부로는 부족
- **1,600만 대를 수용하는 A클래스 사설 대역(10.0.0.0)** 을 내부 방화벽·스위치에 설정
- 부서별 **서브네팅(Subnetting)**: 10.1.x.x(인사팀), 10.2.x.x(개발팀) 식으로 분할해 1만 대 PC에 배분

#### 3단계: NAT를 통한 결합 통신

- 직원 10,000명이 동시에 인터넷에 접속하면, 사내 방화벽(라우터)이 **NAT (Network Address Translation)** 를 수행
- 내부의 A클래스 사설 IP(10.x.x.x)를 통신사에서 임대한 250개의 C클래스 공인 IP(210.10.10.x)로 변환하며 인터넷으로 송출

> **결론**: 외부 인터넷에서는 이 회사가 C클래스(공인 IP) 규모의 작은 건물처럼 보이지만, 방화벽 내부에는 A클래스(사설 IP) 규모의 거대한 네트워크가 안전하게 운영됩니다.

## 실무 적용 사례 (Use Case)

- **고객사 전용회선 개통**: 통신사는 고객사에 공인 IP 블록(/29, /28, /24 등)을 할당하고, 고객사 내부는 사설 대역 + NAT로 설계하도록 안내합니다.
- **사내망·고객사망 설계 표준**: 수용 단말 수에 따라 사설 대역을 선택합니다 — 소규모(수십 대)는 192.168.x.x, 중규모는 172.16~31.x.x, 대규모·확장 예정 조직은 10.x.x.x 권장.
- **망 연동 시 대역 중복 확인**: 두 조직의 사내망을 연동(VPN, 전용선)할 때 양측이 같은 사설 대역(예: 둘 다 192.168.0.x)을 쓰면 충돌하므로, 사전에 대역 조사 후 재설계 또는 NAT 변환을 적용합니다.

## 주의사항 및 FAQ

### 주의사항

- **사설 IP는 인터넷으로 라우팅되지 않음**: 사설 IP 대역이 외부 구간 설정에 들어가면 통신이 되지 않습니다. 외부 공개 서비스는 반드시 공인 IP(또는 포트포워딩/NAT)로 노출해야 합니다.
- **망 연동 전 대역 중복 점검 필수**: 특히 M&A, 그룹사 통합, 고객사 VPN 연동 시 사설 대역 충돌이 잦은 장애 원인입니다.
- **클래스 개념은 참조용**: 현재 실제 주소 할당은 클래스 없는 **CIDR (Classless Inter-Domain Routing)** 방식이 표준입니다. 클래스는 대역 구분·소통용 개념으로 이해해야 합니다.

### FAQ

- **Q. 사설 IP를 쓰는데 어떻게 인터넷이 되나요?**
  - A. 공유기/방화벽의 NAT가 사설 IP를 공인 IP로 변환해 내보내기 때문입니다.

- **Q. 우리 회사는 작은데 10.x.x.x를 써도 되나요?**
  - A. 됩니다. 사설 대역 선택은 규모 제한이 없으며, 향후 확장을 고려하면 오히려 넉넉한 대역이 유리합니다.

- **Q. 공인 IP는 왜 유료인가요?**
  - A. 전 세계에서 유일해야 하는 희소 자원(IPv4)이므로 IANA → 지역 레지스트리 → 통신사를 거쳐 유상 임대됩니다.
