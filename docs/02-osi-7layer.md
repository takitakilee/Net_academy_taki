# [기술 개념] OSI 7계층 (OSI 7 Layer Model)

---

## 문서 요약 (Summary)

**OSI 7계층 (Open Systems Interconnection 7 Layer Model)** 은 국제 표준화 기구 (International Organization for Standardization, ISO)가 개발한 컴퓨터 네트워크 프로토콜 참조 모델로, 네트워크 통신 과정을 7개 계층으로 분리하여 각 계층이 특정 기능을 수행하도록 정의합니다. 통신망 운영 실무에서는 **장애 발생 시 문제 계층을 특정해 원인을 분리(Isolation)하는 공용 언어**로 사용됩니다.

---

## 핵심 개념 (Key Concepts)

### 등장 배경

- 과거에는 서로 다른 통신 시스템이 존재했고, 업체마다 네트워크 장비를 제각각 만들면서 통신 과정에서 충돌이 발생할 수 있는 상황이었음
- 계층을 분리함으로써 **개발 및 유지보수가 용이**해지고, **문제 발생 시 해당 계층에서 해결**이 가능해짐

### 3대 특징

- **모듈화 (Modularity)**: 각 계층은 독립적으로 설계되어, 하나의 계층을 수정해도 다른 계층에 영향을 주지 않음
- **표준화 (Standardization)**: ISO 국제 표준으로 정의되어 다양한 시스템·기기 간 호환성 보장
- **간소화 (Simplification)**: 각 계층이 자신의 역할에만 집중하므로 복잡한 네트워크 통신을 단순화

### 상하 구조 (Hierarchy)

- OSI 7계층은 **상하 구조**로 동작합니다. 예를 들어 5계층이 정상 동작하려면 **1~4계층이 모두 완벽하게 동작**해야 합니다.
- 장애 트러블슈팅 시 **하위 계층(물리)부터 순서대로 점검**하는 이유가 여기에 있습니다.

### 계층 전체 요약표

| 계층 | 계층명 | 기능 | 주요 프로토콜 | 전송 단위 | 대표 장비 |
|---|---|---|---|---|---|
| **7** | 응용 계층 (Application Layer) | 사용자(응용프로그램)를 OSI 환경에 접속시키고 네트워크 서비스 제공 | HTTP, FTP, SMTP, DNS, DHCP, Telnet, SSH | Data | - |
| **6** | 표현 계층 (Presentation Layer) | 데이터 표현·형식 변환, 암호화/복호화, 압축 | JPEG, MPEG, SSL/TLS, SMB | Data | - |
| **5** | 세션 계층 (Session Layer) | 세션 설정·유지·해제, 동기점(대동기점/소동기점) 생성, 대화 제어 | NetBIOS, RPC, NFS, SSH | Data / Message | - |
| **4** | 전송 계층 (Transport Layer) | 포트 번호 기반 응용프로그램 매핑, 신뢰성 있는 전송(분할·재조립, 오류 검출·복구), TCP/UDP 결정 | TCP, UDP | Segment | 게이트웨이 (Gateway) |
| **3** | 네트워크 계층 (Network Layer) | IP 주소 기반 논리적 주소 지정, 최적 경로 탐색(Routing) 및 전달(Forwarding) | IP, ICMP, ARP, RARP, RIP | Packet | 라우터 (Router) |
| **2** | 데이터 링크 계층 (Data Link Layer) | 동일 네트워크(LAN) 내 데이터 교환, 프레이밍, MAC 주소 지정, 오류 검출 | Ethernet, PPP, Token Ring, FDDI, HDLC | Frame | 스위치 (Switch), 브릿지 (Bridge) |
| **1** | 물리 계층 (Physical Layer) | 실제 장비·회선의 물리적 특성 규정, 전기·광 신호로 데이터 전송 | RS-232C, V.35, 케이블 규격 | Bit | 허브 (Hub), 리피터 (Repeater) |

## 구성 및 동작 원리 (Architecture & Mechanism)

### 1계층: 물리 계층 (Physical Layer)

> "실제 장비, 회선과 관련된 특성 규정 (물리적 연결)"

- 네트워크 전송 매체를 통해 데이터를 전송하기 위한 기초 기능 수행. 전기적·물리적·기계적 특성을 결정하고 데이터를 **전기 신호, 광 신호, 전파** 등으로 변환
- **신호 변환**: 0과 1의 나열을 아날로그 신호로 바꾸어 전선으로 흘려보내고, 수신 신호를 다시 0과 1로 해석
- **변환 담당 하드웨어**: 단순 케이블이 아니라 **랜카드 (Network Interface Card, NIC) 내부의 PHY 칩**이나 **트랜시버(Transceiver)** 가 물리적으로 수행

| 항목 | 내용 |
|---|---|
| 핵심 기능 | 물리 매체를 통한 데이터 전송 기능 정의, 기계적/전기적 접속 규칙 정의 |
| 전송 단위 | Bit (비트) |
| 주요 프로토콜/규격 | RS-232, RS-449 등 케이블 규격 |
| 대표 장비 | 허브(Hub), 리피터(Repeater) |

### 2계층: 데이터 링크 계층 (Data Link Layer)

> "LAN 내부(동일 네트워크)에 있는 여러 대의 컴퓨터 간 데이터 교환 및 프레이밍"

- 네트워크 계층의 패킷을 물리 매체에 실어 보내며, 물리 계층에서 발생할 수 있는 오류를 검출·수정
- **프레이밍 (Framing)** — "여기서부터 저기까지가 하나의 택배":
  - 쏟아지는 비트의 나열을 일정 크기로 잘라 **프레임(Frame)** 으로 포장하고, 헤더(Header)와 트레일러(Trailer)로 데이터의 시작과 끝을 표시
- **MAC 주소 지정 (Addressing)** — "누구에게 보내는 택배인가":
  - 랜카드 고유의 물리 주소인 **MAC (Media Access Control) 주소**로 출발지·도착지를 명시하여, 자신에게 온 데이터만 수신
- **오류 검출 (Error Detection)** — "파손 여부 확인":
  - 프레임 끝에 **FCS (Frame Check Sequence)** 검사 코드를 부착. 수신 측에서 변질 판정 시 프레임을 폐기하고 재전송 요청

| 항목 | 내용 |
|---|---|
| 핵심 기능 | 물리 주소 지정(MAC), 오류 제어, 흐름 제어, 프레임 생성 |
| 전송 단위 | Frame (프레임) |
| 주요 프로토콜 | Ethernet, PPP, ALOHA |
| 대표 장비 | 브릿지(Bridge), 스위치(Switch) |

### 3계층: 네트워크 계층 (Network Layer)

> "IP를 사용하여 도착지를 찾고, 라우팅을 통해 최적의 경로를 탐색하는 계층"

- 논리적 주소(IP)를 관리하고, 라우팅 알고리즘으로 패킷을 목적지까지 가장 효율적인 경로로 전달 (Routing + Forwarding)
- **활동 범위**: 2계층이 '같은 네트워크(LAN)' 내부의 "동네 배달"이라면, 3계층은 인터넷 전체를 무대로 한 "전국/해외 배송"
- **주소 비교**:
  - **MAC 주소(2계층)**: 공장에서 새겨져 바뀌지 않는 '주민등록번호' — 물리적 위치 파악 불가
  - **IP 주소(3계층)**: 장소에 따라 새로 부여받는 '우편 번호/집 주소' — 전체 경로 방향 결정 가능
- **장비 비교**: 스위치(2계층)는 내부 네트워크 안에서만 전달, **라우터(Router, 3계층)** 는 네트워크 간 '우편집중국'으로 최적 경로를 계산해 패킷을 다음 목적지로 전달

| 항목 | 내용 |
|---|---|
| 핵심 기능 | 라우팅(최적 경로 결정), 논리적 주소 지정(IP 헤더 배치) |
| 전송 단위 | Packet (패킷) |
| 주요 프로토콜 | IP, RIP, ARP, ICMP |
| 대표 장비 | 라우터(Router) |

### 4계층: 전송 계층 (Transport Layer)

> "포트 번호 관리를 통한 어플리케이션 매핑 및 신뢰성 있는 데이터 전송 제어"

- 두 시스템 간 연결을 설정하고 데이터를 안정적으로 전달. 데이터 분할/재조합, 오류 검출·재전송 등 복구 수행
- **목적지의 디테일**: 3계층은 목적지 '컴퓨터(IP)'까지만 배달하지만, 4계층은 **포트(Port) 번호**로 컴퓨터 내부의 '프로그램'까지 찾아줌 (예: 웹은 80/443, 특정 게임은 3000번 포트)
- **배달 품질**: 3계층은 유실에 책임지지 않는 Best-Effort 방식이지만, 4계층은 서비스 성격에 따라 전송 방식을 결정

#### 전송 프로토콜 비교 (TCP vs UDP)

| 구분 | TCP (Transmission Control Protocol) | UDP (User Datagram Protocol) |
|---|---|---|
| 별명 | "꼼꼼한 택배" | "빠른 총알 배송" |
| 신뢰성 | 보장 (손실 없음, 순서 보장) | 미보장 |
| 연결 방식 | 3-way Handshake 연결 설정, ACK 확인 응답, 4-way Handshake 종료 | 비연결형 (수신 확인 없이 전송) |
| 적합 서비스 | 대용량 파일 전송 등 안정성 중시 | 실시간 스트리밍, 온라인 게임, DNS 등 속도 중시 |

| 항목 | 내용 |
|---|---|
| 핵심 기능 | 포트 기반 End-to-End 제어, 데이터 분할(Segmentation)·재조합, 흐름/오류 제어 |
| 전송 단위 | Segment (세그먼트) |
| 주요 프로토콜 | TCP, UDP |
| 대표 장비 | 게이트웨이(Gateway) |

### 5계층: 세션 계층 (Session Layer)

> "통신을 위한 세션 관리, 연결 설정 및 해제, 동기화"

- 두 프로그램(프로세스) 사이의 논리적 연결인 **세션(Session)** 을 설정·유지·해제하고, 대화의 시작과 끝을 구분
- **대화의 맥락 관리**: 4계층은 데이터를 목적지 포트까지 배달하면 끝이지만, 5계층은 '로그인 유지' 같은 **세션 상태**를 유지·제어 (예: 은행 웹사이트에서 일정 시간 활동이 없으면 "세션 만료" 자동 로그아웃)
- **동기화 (Synchronization)** — "중간부터 이어받기":
  - 전송 중 일정 간격으로 **체크포인트(동기점: 대동기점/소동기점)** 를 생성
  - 10GB 파일을 받다가 9GB 시점에 끊겨도, 5계층 덕분에 마지막 체크포인트(9GB)부터 이어받기 가능
- **통신 방식 결정**: 반이중 (Half-Duplex, 무전기 방식) / 전이중 (Full-Duplex, 전화기 방식)

| 항목 | 내용 |
|---|---|
| 핵심 기능 | 세션 관리, 동기점 생성(대동기점/소동기점), 대화(통신 방식) 제어 |
| 전송 단위 | Data / Message |
| 주요 프로토콜 | NetBIOS, RPC, NFS, SSH 등 |

### 6계층: 표현 계층 (Presentation Layer)

> "송수신 측 간에 데이터를 알맞은 코드 및 형식으로 변환, 암호화, 압축"

- 응용 계층의 데이터를 상대방이 이해할 수 있는 **공통 서식**으로 변환 (또는 역변환)
- **데이터 변환 (Translation)**: 송신 측 코드 체계(예: ASCII)를 수신 측 체계(예: EBCDIC)로 번역하거나 공통 표준(예: UTF-8)으로 통일 — 이미지(JPG, PNG), 비디오(MP4), 텍스트(JSON, XML) 등 파일 포맷 처리와 연관
- **암호화/복호화 (Encryption/Decryption)**: 중간 탈취 방지를 위해 데이터를 암호화하고 목적지에서 복호화 — **HTTPS (SSL/TLS)** 가 대표 사례
- **압축 (Compression)**: 네트워크 부하 감소를 위해 중복 데이터를 압축하고 수신 측에서 해제

| 항목 | 내용 |
|---|---|
| 핵심 기능 | 데이터 포맷 변환(번역), 암호화/복호화, 압축/압축 해제 |
| 전송 단위 | Data |
| 주요 프로토콜/규격 | JPEG, MPEG, SMB, AFP, SSL/TLS 등 |

### 7계층: 응용 계층 (Application Layer)

> "사용자와 직접 상호작용하는 소프트웨어를 지원하고 네트워크 서비스 제공"

- 사용자·응용 프로그램이 네트워크 환경(OSI 환경)에 접근하도록 **직접적인 인터페이스를 제공하는 최상위 계층**
- **흔한 오해**: 크롬(Chrome), 카카오톡 같은 프로그램 자체가 응용 계층이 아니라, 이들이 네트워크와 데이터를 주고받기 위해 사용하는 **공통 통신 규칙(프로토콜)** 이 응용 계층임
- **서비스별 프로토콜 매칭**:
  - 웹 서핑: HTTP / HTTPS
  - 파일 전송: FTP
  - 이메일 송수신: SMTP, POP3 / IMAP
  - 도메인 주소 해석: DNS (도메인 주소를 3계층 IP 주소로 변환)

| 항목 | 내용 |
|---|---|
| 핵심 기능 | 사용자·응용 프로그램의 네트워크 인터페이스, 네트워크 서비스 제공 |
| 전송 단위 | Data |
| 주요 프로토콜 | DHCP, DNS, FTP, HTTP, HTTPS, SMTP, IMAP 등 |

### 통신의 흐름: 캡슐화와 디캡슐화 (Encapsulation & Decapsulation)

웹 브라우저 주소창에서 '엔터'를 치는 순간의 데이터 흐름입니다.

```text
[송신 측]
응용 계층 (HTTP Request 생성)
  ➡ 표현 계층 (암호화/인코딩)
  ➡ 세션 계층 (세션 및 동기점 생성)
  ➡ 전송 계층 (포트 부여 및 세그먼트 분할)
  ➡ 네트워크 계층 (IP 헤더 부착 및 패킷화)
  ➡ 데이터 링크 계층 (MAC 헤더 부착 및 프레임화)
  ➡ 물리 계층 (전기/빛 신호 변환 후 회선 전송)

                ⬇ (물리 전송 매체 이동)

[수신 측]
물리 계층 (신호 수신) ➡ 데이터 링크 계층 ➡ 네트워크 계층
  ➡ 전송 계층 ➡ 세션 계층 ➡ 표현 계층 ➡ 응용 계층 (화면 렌더링)
```

- 송신 측은 위에서 아래로 내려가며 각 계층의 헤더를 붙여 포장(**캡슐화, Encapsulation**)하고, 수신 측은 역순으로 포장을 하나씩 뜯으며(**디캡슐화, Decapsulation**) 최종 데이터를 화면에 표시합니다.

## 실무 적용 사례 (Use Case)

- **장애 대응 시 계층별 원인 분리 (Fault Isolation)**
  - 고객사 회선 장애 접수 시 하위 계층부터 순서대로 점검합니다: ① 1계층 — 광 레벨·케이블·포트 상태(Link Down 여부) ② 2계층 — 스위치 MAC 학습, VLAN 설정 ③ 3계층 — IP 설정, 라우팅 테이블, Ping/ICMP ④ 4계층 이상 — 포트 차단(방화벽), 세션/애플리케이션 이상
- **부서 간 커뮤니케이션 공용 언어**
  - "L2 구간 이상", "L3까지는 정상인데 L4 포트가 막혀 있다"처럼 계층 번호로 장애 범위를 전달하면 유관 부서(인프라 운영, CS, 고객사 담당자) 간 소통이 명확해집니다.
- **장비 도입·설계 시 계층 매핑**
  - 국사·고객사 구성도 설계 시 허브/리피터(L1), 스위치(L2), 라우터(L3), 방화벽·로드밸런서(L4~L7) 등 장비의 동작 계층을 기준으로 역할과 배치를 결정합니다.

## 주의사항 및 FAQ

### 주의사항

- **트러블슈팅은 반드시 하위 계층부터**: 상위 계층은 하위 계층이 모두 정상일 때만 동작합니다. 물리 구간(광 레벨, 커넥터) 확인 없이 상위 설정만 점검하면 원인 파악이 지연됩니다.
- **OSI는 참조 모델**: 실제 인터넷은 TCP/IP 4계층(또는 5계층) 모델로 동작합니다. OSI 7계층은 개념 정리·소통용 참조 모델로 이해해야 하며, 실제 프로토콜이 계층에 1:1로 완벽히 대응하지는 않습니다.

### FAQ

- **Q. 스위치와 라우터의 차이는 무엇인가요?**
  - A. 스위치는 2계층 장비로 MAC 주소 기반으로 동일 네트워크(LAN) 내부에서 데이터를 전달하고, 라우터는 3계층 장비로 IP 주소 기반으로 서로 다른 네트워크를 연결해 최적 경로를 계산합니다. (단, L3 스위치는 라우팅 기능을 포함합니다.)

- **Q. TCP와 UDP는 언제 구분해서 쓰나요?**
  - A. 손실 없이 순서대로 전달돼야 하는 서비스(파일 전송, 웹)는 TCP, 속도가 우선인 서비스(실시간 스트리밍, 게임, DNS)는 UDP를 사용합니다.

- **Q. 크롬 같은 브라우저가 응용 계층인가요?**
  - A. 아닙니다. 브라우저는 소프트웨어이고, 응용 계층은 그 소프트웨어가 네트워크와 통신하기 위해 사용하는 프로토콜(HTTP/HTTPS 등)을 의미합니다.

- **Q. 계층별 데이터 전송 단위를 요약하면?**
  - A. 1계층 Bit → 2계층 Frame → 3계층 Packet → 4계층 Segment → 5~7계층 Data(Message)입니다.
