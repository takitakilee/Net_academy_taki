# [기술 개념] 네트워크 기초와 ISP 구조, 가입자망 기술

---

## 문서 요약 (Summary)

컴퓨터 네트워크는 컴퓨터들이 서로 연결되어 통신하는 체계이며, 개별 LAN은 스위치·라우터를 거쳐 **ISP (Internet Service Provider)** 의 계층 구조(Local → Regional → Global)를 통해 전 세계와 연결됩니다. 이 문서는 네트워크의 기본 연결 원리부터 ISP의 동작, 가정·기업을 잇는 가입자망 기술(Dial-up, DSL, Cable, FTTx)까지의 흐름을 다룹니다.

---

## 핵심 개념 (Key Concepts)

### 네트워크란

- 사람들이 서로 연결되어 있으면 **휴먼 네트워크**, 컴퓨터들이 서로 연결되어 통신할 수 있으면 **컴퓨터 네트워크**
- 컴퓨터 두 대의 연결은 **케이블**이 가장 간단한 방법

### 전송 매체: UTP / STP 케이블

- **UTP (Unshielded Twisted Pair)**: 주변에서 흔히 보는 랜 케이블. 색깔별로 2가닥씩 꼬인 8가닥의 선으로 구성 — **전자파 간섭을 줄이기 위해 꼬아서** 사용
  - 녹색·주황색: 데이터 통신 / 갈색: 전원 공급·접지 / 청색: 전화
- **STP (Shielded Twisted Pair)**: 꼬인 선들을 호일로 한 번 더 감싸 간섭을 추가로 차단. 유럽에서 주로 사용하며, 아시아·미국은 UTP가 주류

### 연결 장비의 등장

- 3대 이상 연결 시 컴퓨터마다 선을 직접 연결하면 선이 기하급수적으로 늘어남 → **허브(Hub)·스위치(Switch)** 등장
- 허브와 스위치는 세부 동작은 다르지만, **하나의 네트워크 안의 컴퓨터를 연결**한다는 점은 동일
- 스위치로 컴퓨터를 연결하는 구조를 **스타 토폴로지 (Star Topology)** 라고 부름
- 서로 다른 회사(네트워크)를 분리·연결하려면 스위치가 아닌 **라우터(Router)** 가 필요

### ISP (Internet Service Provider)

- 우리 회사에 속하지 않은 **다른 네트워크와 연결해 주는 라우터들이 있는 곳** = ISP (예: KT, SK브로드밴드, LG U+)
- ISP 계층 구조:
  - **Local ISP**: 개별 가입자·기업을 수용 (하나의 도시에 여러 개 존재)
  - **Regional (National) ISP**: Local ISP들을 연결
  - **Global ISP**: 여러 국가에 걸쳐 대규모 해저 케이블·인프라를 보유한 최상위 사업자. 국내 통신 3사도 자체 해저케이블과 해외 POP (Point of Presence)를 통해 글로벌 회선 제공
- **종단 간 통신 경로**: A 컴퓨터 → (스위치) → Local ISP → Regional → Global → Regional → Local → B 컴퓨터

## 구성 및 동작 원리 (Architecture & Mechanism)

### ISP의 작동 원리

1. **사용자 연결**: 사용자가 ISP에 가입하면 ISP가 IP 주소를 할당하고 인터넷 접속 경로를 설정
2. **백본 네트워크 (Backbone)**: ISP는 백본망을 통해 지역·글로벌 인터넷과 연결
3. **라우터와 스위치**: ISP 망 내부에서 데이터를 올바른 경로로 전송
4. **DNS (Domain Name System) 서버**: 도메인 이름을 IP 주소로 변환하는 '인터넷 전화번호부'
   - 도메인-IP 변환: 호스트 이름(google.com)을 IP 주소(142.250.190.46)로 매핑
   - DNS 쿼리 처리: 주소 요청 시 해당 IP를 찾아 응답

### 가입자망 기술의 진화 (Local ISP ↔ 가정/기업 연결)

각 가정까지 전용선을 새로 깔면 막대한 비용이 들기 때문에, **이미 놓여 있는 선을 활용**하는 방향으로 기술이 발전했습니다.

| 기술 | 사용 매체 | 원리 및 특징 | 한계 |
|---|---|---|---|
| **Dial-up** | 전화선 | 하나의 전화선으로 전화와 데이터 통신을 겸용 | 전화 중 데이터 통신 불가 (동시 사용 불가) |
| **DSL (Digital Subscriber Line)** | 전화선 (구리, 0Hz~1,104kHz) | 음성은 0~4kHz만 사용하므로, **남는 주파수 대역**을 데이터에 활용 → 전화·인터넷 동시 사용 | 전화국과의 거리가 멀수록 속도 감소 |
| **Cable** | 케이블 TV 회선 | 방송 채널 대역 외 **남는 대역폭**을 데이터 통신에 활용 | 하나의 선을 여러 가구가 공유 → 주변 사용량이 많으면 속도 저하 |
| **FTTx (광케이블)** | 광섬유 | 대역폭이 넓고 속도가 매우 빨라 인터넷+IPTV+인터넷전화 동시 제공 | 별도 광 인프라 구축 필요 |

#### DSL 세부 구분: ADSL vs SDSL

| 구분 | ADSL (Asymmetric DSL) | SDSL (Symmetric DSL) |
|---|---|---|
| 대역폭 배분 | 하향(다운로드) > 상향(업로드) | 하향 = 상향 (동일) |
| 적합 대상 | 일반 가정 (다운로드 위주 사용 패턴) | 화상회의, 서버 운영, 클라우드 등 상/하향이 비슷한 기업·사업장 |

#### FTTx 세부 구분

- **FTTH (Fiber To The Home)**: 광케이블이 **집안까지** 인입
- **FTTB (Fiber To The Building)**: 광케이블은 **건물까지**, 건물 내부는 구리선으로 각 세대 연결
- 신축 아파트는 단지까지 광케이블을 포설하고 분배기로 각 세대에 공급

## 실무 적용 사례 (Use Case)

- **가입자 수용 설계**: 신규 아파트 단지·상가 수용 시 기존 인입 매체(전화선/케이블/광)를 조사해 FTTH/FTTB 등 최적 수용 방식을 결정합니다.
- **기업 고객 제안**: 업로드 트래픽이 많은 고객(서버 운영, 화상회의 센터)에게는 대칭형 회선(광 전용회선 등)을, 일반 사무 환경에는 비대칭 상품을 제안합니다.
- **속도 저하 민원 대응**: DSL 계열은 국사와의 거리, Cable은 지역 공유 사용량이 속도의 주요 변수임을 이해하면 민원 원인 분석이 빨라집니다.

## 주의사항 및 FAQ

### 주의사항

- **매체별 속도 변수 상이**: DSL은 '거리', Cable은 '동시 사용자 수'가 병목입니다. 동일 상품이라도 환경에 따라 체감 속도가 다릅니다.
- **UTP 전송 거리 한계**: UTP 케이블의 최대 전송 거리는 약 100m로, 초과 구간은 허브/스위치 또는 광 변환으로 연장해야 합니다.

### FAQ

- **Q. 허브와 스위치는 무엇이 다른가요?**
  - A. 둘 다 하나의 네트워크 안의 장비를 연결하지만, 허브는 수신 데이터를 모든 포트로 뿌리고(플러딩) 스위치는 MAC 주소를 학습해 목적지 포트로만 전달합니다. (상세: 네트워크 장비 문서 참조)

- **Q. 라우터는 언제 필요한가요?**
  - A. 서로 다른 네트워크(예: 우리 회사 ↔ 다른 회사, 사내망 ↔ 인터넷)를 연결·분리할 때 필요합니다.

- **Q. 지금도 DSL이나 Cable을 쓰나요?**
  - A. 국내는 FTTH가 주류이지만, 구축 여건에 따라 FTTB+구리선, Cable 방식이 혼재합니다. 지역·건물별 인입 환경 확인이 필요합니다.
