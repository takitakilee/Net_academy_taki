# [기술 개념] 네트워크 장비와 통신국사 (허브·스위치·라우터, 국사의 역할)

---

## 문서 요약 (Summary)

통신장비는 크게 데이터를 장거리·대용량으로 실어 나르는 **전송장비(대동맥)** 와, 데이터를 개별 사용자·기기에 배달하는 **네트워크 장비(교차로와 골목길)** 로 나뉩니다. 이 문서는 장비 분류 체계와 허브·스위치·라우터의 동작 차이, 그리고 모든 회선이 집결하는 **통신국사(局舍)** 의 역할을 다룹니다.

---

## 핵심 개념 (Key Concepts)

### 통신장비의 분류 체계

| 구분 | 통신장비 (최상위 개념) | 전송장비 (Transmission Equipment) | 네트워크 장비 (Network Equipment) |
|---|---|---|---|
| 비유 | - | 도시와 도시를 잇는 **광역 고속도로** | 도시 내부의 **교차로·신호등·일반 도로** |
| 범위 | 유선·무선·광 등 모든 매체의 정보 송수신 하드웨어 전체 (단말기~위성 장비) | 통신사 간·도시 간 백본 구간 | 건물 내부, 사무실, 가정 내 망 |
| 핵심 역할 | 정보의 생성·송수신·처리 | 여러 신호를 하나로 묶어(다중화) 장거리 전송 후 다시 분리 | 패킷 주소를 읽어 경로 지정·분배 (Routing/Switching) |
| 동작 계층 | - | 물리 계층(L1) + 데이터 링크 계층(L2) 일부 | L2 + 네트워크 계층(L3) 중심 |
| 주요 장비 | 기지국 장비, 위성 안테나, 전화 교환기, 모뎀 등 | WDM/DWDM, MSPP, PTN | 라우터, 스위치, 공유기 |

### 프로토콜 (Protocol)

- 컴퓨터·통신 장비 사이에서 데이터를 원활하게 주고받기 위해 약속한 **통신 규약·규칙 체계**
- 데이터 전송 형식, 오류 처리, 신호 처리, 인증 방식 등을 정의 (예: HTTP — 하이퍼텍스트 전송 프로토콜)

## 구성 및 동작 원리 (Architecture & Mechanism)

### 허브 vs 스위치 vs 라우터

#### 허브 (Hub) — L1

- 전기 신호를 증폭해 LAN의 전송 거리를 연장하고, 여러 장비를 LAN에 접속시키는 장비 (UTP 환경의 콘센트레이터 역할)
- UTP 케이블의 최대 전송 거리 100m를 허브로 연장 가능
- **한계**: 수신한 데이터 프레임을 연결된 **모든 장비에 전송(플러딩, Flooding)** → 충돌이 많아 하나의 허브에 많은 장비를 연결할 수 없음

#### 스위치 (Switch) — L2

- **MAC 주소 테이블**(MAC 주소 + 포트 번호)을 보유하여, 목적지 MAC 주소를 가진 장비가 연결된 **해당 포트로만** 프레임 전송
- 포트 간 충돌이 없어 **네트워크 성능 향상 + 보안성 강화**
- **한계**: 브로드캐스트 프레임은 모든 포트로 전송 → 접속 장비가 많아질수록 브로드캐스트 트래픽 증가로 성능 저하
- ※ 플러딩: 일단 모든 포트로 뿌리고, 응답한 장비가 생기면 그때부터 기록(학습)하여 해당 포트로만 전송

#### 라우터 (Router) — L3

- **IP 주소 등 3계층 주소를 참조**하여 목적지와 연결되는 포트로 패킷 전송
- **서브넷(Subnet)** 이 다른 장비 간 통신은 반드시 L3 장비를 거쳐야 함 (※ 서브넷: 하나의 큰 네트워크를 관리하기 쉽게 쪼갠 부분 네트워크)
- 스위치는 멀티캐스트·브로드캐스트·목적지 미상 유니캐스트를 플러딩하지만, **L3 장비는 이런 프레임을 모두 차단** → 네트워크 분리·보안
- 추가 기능: 최적 경로 탐색, 허가된 데이터만 통과(보안), 서로 다른 통신 규격 연결(프로토콜 변환)

#### L2 스위치 vs L3 스위치

| 구분 | L2 스위치 | L3 스위치 |
|---|---|---|
| 참조 주소 | MAC 주소 | IP 주소 (+ MAC) |
| 통신 범위 | 같은 네트워크(LAN) 내부 | 서로 다른 네트워크 간 (라우팅 기능 수행) |
| 요약 | 같은 동네 안에서 MAC 주소로 길 찾기 | L2 기능 + 라우터 역할 겸비 |

### 무선 공유기에 '라우터'라는 이름이 붙는 이유

무선 공유기는 **라우터 + 스위치 + AP** 세 장비의 기능이 통합된 장비입니다.

1. **라우터 기능**: 통신사의 '공인 IP(외부 망)'와 집안의 '사설 IP(내부 망)' 사이의 통로 역할, **DHCP (Dynamic Host Configuration Protocol)** 로 기기별 IP 할당, 패킷 경로 배정(교통정리)
2. **스위치 기능**: 뒷면의 여러 LAN 포트로 유선 기기 연결
3. **AP (Access Point) 기능**: 전기 신호를 무선 신호(Wi-Fi)로 변환하여 송출

### 통신국사(局舍)의 역할

> 국사: 특정 지역의 모든 통신 회선이 집결하고 분산되는 **네트워크 허브**

- **회선 집선 및 분배**: 각 가정·기업에서 오는 수만 개의 선을 하나로 모아 상위망으로 보내고, 외부 데이터를 각 사용자에게 전달
- **신호 변환 및 증폭**: 장거리 이동으로 약해진 빛·전기 신호를 재증폭하거나 데이터 규격에 맞게 변환
- **교환 및 라우팅**: 데이터가 목적지로 가도록 길을 찾아주는 **대형 스위치·라우터 장비 밀집**

#### 국사의 대형 스위치 특징

- **막대한 처리량**: 수만 개 광케이블을 지연 없이 처리하는 엔진
- **포트 밀집도**: 수백~수천 개의 선을 한 장비에서 통합 관리
- **가상화 기술**: 하나의 거대한 장비를 논리적으로 분할하여, A팀과 B팀이 서로 데이터를 볼 수 없도록 논리적 벽(망 분리)을 구성

#### 국사에서 회사까지의 연결

- **광전송 기술 (WDM/DWDM)**: 하나의 광케이블에 여러 파장의 빛을 실어, 케이블 하나로 수십 배의 데이터 전송 — 전용회선 구성의 핵심 기술
- **메트로 이더넷**: 국사에서 회사 건물까지 광케이블로 연결하고 이더넷 방식으로 통신 — 설치 간편, 비용 효율 우수

## 실무 적용 사례 (Use Case)

- **고객사 망 설계**: 층·부서 단위는 L2 스위치, 부서 간·인터넷 연동 구간은 L3 스위치/라우터로 구성해 브로드캐스트 도메인을 분리합니다.
- **국사 수용 설계**: 신규 가입자·기업 회선은 국사의 집선 장비에 수용한 뒤 WDM/DWDM 백본으로 상위망에 연결합니다.
- **테넌트 분리**: 국사 대형 스위치의 가상화 기술로 고객사별 논리적 망 분리를 제공합니다 (고객사 망분리 요구 대응).

## 주의사항 및 FAQ

### 주의사항

- **브로드캐스트 도메인 크기 관리**: 하나의 L2 망에 장비가 너무 많으면 브로드캐스트 트래픽으로 성능이 저하됩니다. 적절한 서브넷 분할(L3 분리)이 필요합니다.
- **장비 계층 혼동 주의**: "스위치"라는 이름이라도 L3 스위치는 라우팅을 수행합니다. 장비 명칭이 아니라 **동작 계층**으로 역할을 판단해야 합니다.

### FAQ

- **Q. 허브는 요즘도 쓰나요?**
  - A. 충돌 문제로 실무에서는 거의 스위치로 대체되었습니다. 개념적으로 L1 동작 원리(플러딩·증폭)를 이해하는 용도로 알아두면 됩니다.

- **Q. L3 스위치가 있는데 라우터는 왜 필요한가요?**
  - A. L3 스위치는 내부망 간 고속 라우팅에 적합하고, 라우터는 WAN 연동·프로토콜 변환·정교한 정책 제어에 강점이 있어 백본·대외 구간에 사용합니다.

- **Q. 국사 장애가 나면 어떤 영향이 있나요?**
  - A. 국사는 지역 회선의 집결지이므로 해당 지역 가입자 전체에 영향이 갈 수 있습니다. 이 때문에 국사 간 링 구조·이중화 구성이 필수입니다.
