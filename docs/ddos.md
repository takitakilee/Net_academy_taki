# DDoS 공격과 클린존(Clean Zone) 서비스의 이해

> **대상 독자**: 통신/네트워크 도메인 신입사원 및 B2B 영업 실무자
> **문서 목적**: DDoS 공격의 원리, 클린존 서비스의 동작 방식, 방화벽·WAF·CDN과의 역할 구분, 그리고 대역폭 공격의 다양한 대응 방법을 체계적으로 이해한다.

## 1. DDoS 공격이란 무엇인가

**DDoS(Distributed Denial of Service, 분산 서비스 거부 공격)**는 다수의 감염된 PC·서버(봇넷)를 동원해 표적의 자원을 고갈시켜 **정상 사용자가 서비스를 이용하지 못하게 만드는 공격**이다.

핵심은 "해킹해서 침입"하는 것이 아니라는 점이다. 비유하자면 **문 앞에 가짜 손님 수백만 명을 세워서 진짜 손님이 못 들어오게 하는 것**이다. 시스템에 침투하거나 데이터를 훔치는 것이 아니라, 단순히 자원을 소진시켜 서비스를 마비시킨다.

> 💡 **용어 설명**
>
> - **봇넷(Botnet)**: 악성코드에 감염되어 공격자가 원격 조종할 수 있는 좀비 PC/서버들의 네트워크. 공격자는 수만~수백만 대의 봇을 동시에 조종해 공격 트래픽을 발생시킨다.
> - **IP 스푸핑(IP Spoofing)**: 패킷의 출발지 IP 주소를 위조하는 것. 공격자가 자신의 위치를 숨기고, 추적·차단을 어렵게 만든다. "누가 쏘는지 찾아서 차단"이 근본적으로 어려운 이유다.

### 1.1 공격 유형 3가지 — 무엇을 고갈시키는가

| 유형 | 고갈 대상 | 대표 기법 | 규모 |
|---|---|---|---|
| **대역폭 소진형 (Volumetric)** | 회선 용량 (파이프) | UDP Flood, ICMP Flood, DNS/NTP 증폭 | 수십 Gbps ~ Tbps급 |
| **프로토콜/자원 소진형** | 장비의 세션 테이블 | SYN Flood | 트래픽은 적어도 장비가 먼저 마비 |
| **애플리케이션 계층형 (L7)** | 서버 CPU·DB·커넥션 | HTTP GET/POST Flood, Slowloris | 수십 Mbps로도 서버 마비 가능 |

> 💡 **용어 설명**
>
> - **UDP/ICMP Flood**: 의미 없는 패킷을 대량으로 쏟아부어 회선을 채우는 공격. 패킷 내용은 중요하지 않고 양이 무기다.
> - **증폭 공격(Amplification)**: 인터넷에 열려 있는 DNS·NTP 서버에 출발지 IP를 피해자로 위조한 작은 요청을 보내면, 서버가 수십~수백 배 큰 응답을 피해자에게 쏘게 된다. 공격자는 적은 비용으로 거대한 트래픽을 만들 수 있다. (반사 공격 Reflection이라고도 부른다)
> - **SYN Flood**: TCP 연결 절차(3-way Handshake: 접속 요청 → 응답 → 확인)를 절반만 진행하고 방치하는 공격. 서버·방화벽은 "연결 대기" 상태를 계속 기억해야 하므로 세션 테이블이 고갈되어 마비된다.
> - **Slowloris**: HTTP 요청을 아주 느리게, 끝내지 않고 보내면서 웹서버의 연결(커넥션)을 계속 점유하는 공격.

### 1.2 대역폭 공격 vs L7 공격 — 결정적 차이

식당에 비유하면:

- **대역폭 공격** = 식당 앞 **도로를 트럭 수천 대로 막아버리는 것**. 가게에 아무도 도달하지 못한다.
- **L7 공격** = 멀쩡하게 입장한 손님들이 자리마다 앉아 **"메뉴 전부 하나씩 설명해주세요"를 무한 반복**하는 것. 도로도 입구도 멀쩡한데 주방이 마비된다.

| 구분 | 대역폭 공격 | L7 공격 |
|---|---|---|
| 고갈 대상 | 회선 용량 (파이프) | 서버 자원 (CPU/커넥션/DB) |
| 트래픽 규모 | 매우 큼 (Gbps~Tbps) | 작음 (Mbps로도 충분) |
| 패킷 성격 | 내용 무의미, 양으로 승부 | 정상 요청과 구분 어려움 |
| 탐지 난이도 | 낮음 (총량으로 즉시 드러남) | 높음 (행위 분석 필요) |
| 주 방어 지점 | **ISP 클린존** | **고객단 WAF/CDN** |

L7 공격이 위험한 이유는 **비대칭성**이다. 공격자의 HTTP 요청 하나는 비용이 거의 없지만, 서버는 그 요청을 처리하기 위해 DB 조회와 페이지 생성을 해야 한다. 공격자 비용 대비 피해자 비용이 수백 배다. 게다가 요청 하나하나가 정상적인 형식이라 탐지가 어렵고, HTTPS로 암호화되어 있으면 ISP 구간에서는 내용을 볼 수조차 없다.

> 💡 **용어 설명**
>
> - **L3/L4/L7**: OSI 7계층 모델의 계층 번호. L3(네트워크 계층)는 IP 주소, L4(전송 계층)는 TCP/UDP 포트, L7(응용 계층)은 HTTP 같은 실제 서비스 내용을 다룬다. "L7 공격"이란 곧 "애플리케이션(웹서비스) 내용 수준의 공격"이라는 뜻이다.
> - **HTTPS/TLS**: 웹 통신을 암호화하는 프로토콜. 중간에서 내용을 볼 수 없게 하므로 보안에 필수지만, 역설적으로 ISP가 L7 공격을 식별하기 어렵게 만드는 요인이기도 하다.

## 2. "DDoS를 막는다"는 것의 의미 — 클린존의 동작 원리

DDoS를 막는다는 것은 공격이 안 오게 하는 것이 아니다. **공격 트래픽과 정상 트래픽을 분리해서, 정상 트래픽만 고객에게 전달하는 것**이다.

### 2.1 왜 고객 스스로는 못 막는가

고객이 1G 전용회선을 쓰는데 10G 공격이 오면, 고객이 방화벽으로 무엇을 하든 **이미 회선이 꽉 차서 게임이 끝난 상태**다. 대역폭 공격은 병목 지점보다 **상류(Upstream)**에서만 막을 수 있다는 물리 법칙이 성립한다. 이것이 ISP 차원의 방어 서비스, 즉 클린존이 필요한 근본 이유다.

> 💡 **용어 설명**
>
> - **상류(Upstream)/하류(Downstream)**: 트래픽이 흘러오는 방향 기준으로, 인터넷 쪽(트래픽이 들어오는 쪽)이 상류, 고객 쪽이 하류다. 물이 넘치는 것을 막으려면 좁은 관(고객 회선)에 도달하기 전, 넓은 상류에서 막아야 한다.
> - **클린존(Clean Zone) / 스크러빙 센터(Scrubbing Center)**: ISP 백본망에 설치된 대형 트래픽 정화 시설. 오염된 트래픽을 끌어들여 세탁(Scrubbing)한 뒤 깨끗한 트래픽만 내보낸다.

### 2.2 클린존 동작 4단계

**1단계. 탐지 (Detection)**
백본 라우터의 NetFlow/sFlow 통계를 상시 분석한다. 특정 고객 IP 대역으로 향하는 트래픽이 평소 패턴을 벗어나면(임계치 초과) 공격으로 판정한다.

> 💡 **NetFlow/sFlow**: 라우터가 자신을 지나가는 트래픽의 통계 정보(출발지·목적지·양 등)를 요약해 분석 시스템으로 보내주는 기능. 전수 검사가 아니라 통계 요약이므로 백본급 대용량에서도 실시간 감시가 가능하다.

**2단계. 우회 (Diversion)**
공격당하는 IP 대역(보통 /24 단위)의 경로를 클린존 장비가 **BGP로 More-specific 광고**한다. BGP는 더 구체적인 경로를 우선하는 규칙이 있으므로, 망 내 모든 라우터가 해당 대역행 트래픽을 클린존으로 보내기 시작한다. 이 시점에는 공격이든 정상이든 전부 클린존으로 끌려온다.

> 💡 **용어 설명**
>
> - **BGP(Border Gateway Protocol)**: 인터넷의 길찾기 프로토콜. 각 네트워크(AS)가 "이 IP 대역은 나한테 오면 된다"고 서로 광고하며, 라우터들은 이 광고를 바탕으로 경로를 결정한다.
> - **More-specific 광고**: BGP는 넓은 대역(예: /16)보다 좁은 대역(예: /24)의 광고를 우선한다. 클린존이 피해 대역을 더 좁은 단위로 광고하면, 기존 경로를 제치고 트래픽을 자신에게 끌어올 수 있다. 이 원리가 클린존 트래픽 유인의 핵심이다.
> - **/24 (프리픽스 표기)**: IP 대역의 크기 표기. /24는 IP 주소 256개짜리 묶음(예: 210.100.5.0~210.100.5.255)이다. 숫자가 클수록 좁은 대역이다.

**3단계. 정화 (Scrubbing)**
Anti-DDoS 전용 장비가 공격 패킷만 걸러낸다. SYN 검증(진짜 접속 의사가 있는지 확인), 출발지 평판 조회, 프로토콜 이상 여부, 행위 분석 등의 기법을 조합한다.

**4단계. 재주입 (Re-injection)**
살아남은 정상 트래픽만 **GRE 터널이나 별도 VRF/MPLS 경로**로 원래 목적지에 돌려보낸다. 일반 라우팅으로 돌려보내면 2단계의 BGP 광고 때문에 다시 클린존으로 끌려오는 루프가 생기므로, 반드시 우회 광고의 영향을 받지 않는 별도 경로를 쓴다.

> 💡 **용어 설명**
>
> - **GRE 터널(Generic Routing Encapsulation)**: 패킷을 다른 패킷 안에 감싸서(캡슐화) 논리적인 전용 통로를 만드는 기술. 중간 라우터들은 겉포장만 보고 배달하므로, 안에 든 트래픽은 일반 라우팅 규칙(BGP 우회 광고)의 영향을 받지 않는다.
> - **VRF(Virtual Routing and Forwarding)**: 하나의 물리 라우터 안에 논리적으로 분리된 여러 개의 라우팅 테이블을 만드는 기술. "같은 장비 위의 별도 가상 도로"라고 보면 된다.
> - **MPLS(Multi-Protocol Label Switching)**: 패킷에 라벨을 붙여 IP 라우팅과 무관하게 미리 정한 경로로 전달하는 백본 기술.

### 2.3 다른 방식과의 비교

- **블랙홀링(RTBH)**: 공격당하는 IP행 트래픽을 통째로 버리는 것. 정상 트래픽까지 죽으므로 "공격자가 원하는 서비스 중단"을 ISP가 대신 완성해주는 셈이다.
- **고객사 자체 장비(온프레미스)**: L7 공격에는 유효하지만, 회선 용량을 넘는 대역폭 공격 앞에서는 무력하다.
- **클린존**: 고객 회선에 도달하기 전, ISP 백본 상단에서 대용량 공격을 흡수하면서 **정상 트래픽은 살린다**. 이것이 클린존의 존재 가치다.

## 3. IX 국사 설치와 라우팅 커버리지

### 3.1 왜 IX 국사에 설치하는가

**IX(Internet eXchange)** 국사는 타 ISP·해외망과 피어링하는 **외부 트래픽의 유입 관문**이다. DDoS 공격 트래픽의 절대다수는 외부(해외 봇넷, 타 통신사 가입자)에서 오므로, 유입 관문에 스크러빙 인프라를 두면 **공격이 백본 내부로 퍼져 백본 대역폭을 잡아먹기 전에** 잘라낼 수 있다.

> 💡 **용어 설명**
>
> - **IX(Internet eXchange)**: 여러 ISP가 한 장소에 모여 서로 트래픽을 교환(피어링)하는 접속점. 국내에서는 KINX, KT-IX, SKB-IX 등이 있다.
> - **피어링(Peering)**: ISP끼리 상호 트래픽을 직접 교환하기로 하고 회선을 연결하는 것.
> - **국사(局舍)**: 통신사의 네트워크 장비가 설치된 건물/시설. 통신 인프라의 물리적 거점이다.
> - **백본(Backbone)**: 통신사 네트워크의 중심이 되는 대용량 기간망. 각 지역·가입자망을 연결하는 고속도로에 해당한다.

### 3.2 핵심 질문 — 다른 경로로 들어오는 공격은 못 막지 않나?

**답: 물리적 설치 위치와 논리적 커버리지는 별개다.**

클린존은 BGP 우회 방식으로 동작하기 때문에 **유입점이 어디든 커버된다**. 클린존이 피해 대역을 More-specific으로 광고하는 순간, 그 광고는 iBGP를 통해 망 전체에 전파된다. 공격 트래픽이 A IX로 들어오든, B 국제관문으로 들어오든, 타 ISP 직접 피어링 지점으로 들어오든, 유입 직후 첫 라우터가 "이 대역은 클린존행"임을 이미 알고 있으므로 결국 클린존을 거치게 된다.

즉, 장비가 IX 국사에 "있는" 것이지, 그 국사로 들어오는 트래픽"만" 처리하는 것이 아니다. 대형 ISP는 주요 관문 국사 여러 곳에 스크러빙 용량을 분산 배치해서, 트래픽을 멀리 끌고 오는 비용(백본 부하·지연)도 줄인다.

> 💡 **iBGP(internal BGP)**: 같은 통신사(AS) 내부의 라우터들끼리 경로 정보를 공유하는 BGP. 클린존의 우회 광고가 망 전체 라우터에 전파되는 통로다.

### 3.3 알아둘 한계와 잔여 리스크

- **탐지~우회 사이의 공백**: 상시(Always-on) 정화가 아니라 탐지 후 우회(On-demand) 방식이면, 공격 시작부터 BGP 광고 전파까지 수십 초~수 분간은 공격이 고객까지 그대로 흘러간다. 이 시간을 얼마나 줄이느냐가 서비스 품질의 차이다.
- **망 내부 발원 공격**: 같은 ISP 가입자의 감염 PC가 망 내 다른 고객을 공격하면 IX를 거치지 않는다. 이 경우도 BGP 우회로 클린존까지 끌고 올 수는 있지만, 그 사이 내부 백본 구간에는 공격 트래픽이 실린다.
- **우회 단위의 한계**: BGP 우회는 보통 /24 단위라, 그 대역 안의 정상 서비스 트래픽도 전부 클린존을 경유하며 약간의 지연이 생긴다.
- **정화 용량 초과**: 스크러빙 센터 용량을 넘는 초대형 공격은 상류(해외 구간) 차단이나 블랙홀링을 병행해야 할 수 있다.
- **L7·암호화 트래픽**: HTTPS로 들어오는 애플리케이션 공격은 ISP가 내용을 볼 수 없어 클린존의 정화율이 떨어진다. 고객단 WAF/CDN과의 역할 분담이 필요한 영역이다.

## 4. 방화벽 · WAF · CDN — 역할 구분

세 가지 모두 "트래픽을 걸러주는 장치"라 헷갈리기 쉽지만, **어느 계층에서 무엇을 기준으로 거르느냐**가 다르다.

건물에 비유하면: 방화벽은 **건물 출입구 경비원**(출입증 확인 — 누가, 어느 문으로), WAF는 **은행 창구 앞 보안요원**(창구에서 하는 말과 행동을 검사), CDN은 **전국에 세운 지점 창구**(본점까지 안 와도 근처에서 일 처리)다.

### 4.1 방화벽 (Firewall)

가장 기본적인 장치로, **L3/L4 (IP 주소와 포트) 기준으로 통과/차단을 결정**한다.

- **판단 기준**: 출발지 IP, 목적지 IP, 포트 번호, 프로토콜. "외부에서 서버 80/443 포트로 오는 것은 허용, 나머지 포트는 차단" 같은 규칙(정책, Policy)의 집합.
- **Stateful 방화벽**: 내부에서 시작한 연결의 응답 트래픽을 자동 통과시키기 위해 세션 상태를 기억한다. 역설적으로 이 세션 테이블 때문에 SYN Flood 공격에는 방화벽 자신이 먼저 죽는 표적이 되기도 한다.
- **한계**: 포트가 열려 있으면 그 안의 내용은 못 본다. 웹서비스를 하려면 443 포트는 열어야 하는데, 방화벽에게는 정상 사용자의 HTTPS 요청과 공격자의 HTTPS 요청이 똑같아 보인다. "어느 문으로 들어오는가"만 보고 "들어와서 무슨 말을 하는가"는 모른다.

> 💡 **용어 설명**
>
> - **포트(Port)**: 하나의 서버에서 여러 서비스를 구분하는 번호. 웹(HTTP)은 80, 보안웹(HTTPS)은 443, 메일 등 서비스마다 정해진 번호가 있다. "문(門)"에 해당한다.
> - **Stateful**: 연결의 상태(누가 언제 연결을 시작했는지)를 기억하며 동작하는 방식. 반대는 Stateless(패킷 하나하나를 독립적으로 판단).
> - **NGFW(Next-Generation Firewall)**: 기존 방화벽에 애플리케이션 식별, IPS(침입방지) 기능을 얹은 차세대 방화벽. 다만 웹 공격 방어의 전문성은 WAF에 못 미친다.

### 4.2 WAF (Web Application Firewall)

이름에 방화벽이 들어가지만 완전히 다른 장비다. **L7, 즉 HTTP/HTTPS 요청의 내용을 열어보고 판단**한다.

- **판단 기준**: URL, 파라미터, 헤더, 쿠키, 요청 본문. "이 파라미터에 SQL 구문이 들어있다(SQL Injection)", "이 입력값에 스크립트가 섞여 있다(XSS)", "이 IP가 로그인 페이지를 초당 50번 호출한다(L7 DDoS)" 같은 것을 본다.
- **TLS 복호화가 전제**: 내용을 보려면 WAF에 서버 인증서를 설치해 암호화를 풀고 검사한 뒤 다시 서버로 보내야 한다. 그래서 WAF는 서비스 운영 주체(고객) 쪽에 놓일 수밖에 없다. "L7 공격은 클린존이 다 못 막고 고객단 몫"인 이유가 이것이다.
- **방화벽과의 관계**: 방화벽이 "443 포트만 열어둠" → 그 443으로 들어온 트래픽의 내용 검사는 WAF 담당. **대체재가 아니라 직렬로 함께 놓는 보완재**다.
- **형태**: 전용 장비, 소프트웨어, 클라우드형(Cloudflare, AWS WAF 등).

> 💡 **용어 설명**
>
> - **SQL Injection**: 웹 입력창에 데이터베이스 명령어(SQL)를 몰래 끼워 넣어 DB를 조작·탈취하는 공격.
> - **XSS(Cross-Site Scripting)**: 웹페이지에 악성 스크립트를 심어 다른 사용자의 브라우저에서 실행되게 하는 공격.
> - **TLS 복호화**: 암호화된 HTTPS 통신을 중간에서 풀어 내용을 검사하는 것. 서버의 인증서(암호 열쇠)를 가진 장비만 가능하다.

### 4.3 CDN (Content Delivery Network)

원래는 보안 장비가 아니라 **성능 인프라**인데, 구조상 강력한 DDoS 방어 효과가 따라온다.

- **기본 개념**: 원본 서버(Origin)의 콘텐츠(이미지, 영상, 정적 페이지)를 전국/전 세계에 분산된 **캐시 서버(Edge, PoP)**에 복사해두고, 사용자를 가장 가까운 엣지로 접속시킨다. 응답이 빨라지고 원본 서버 부하가 줄어든다.
- **접속 유도 방식**: 고객이 DNS를 CDN 쪽으로 위임하면(CNAME), 접속 시 CDN이 사용자 위치에 맞는 엣지 IP를 응답한다. 그 결과 **원본 서버의 실제 IP가 외부에 노출되지 않는다.**
- **DDoS 방어 효과 2가지**:
  1. 공격 트래픽이 전 세계 수백 개 엣지로 **자연 분산**된다. 원본 하나에 모이면 치명적인 공격도 수백 개 지점에 쪼개지면 감당 가능하다. 대형 CDN의 총 수용량은 수백 Tbps급이다.
  2. 원본 IP가 숨겨져 있어 **공격자가 원본을 직접 때릴 수 없다.** (단, 원본 IP가 과거 DNS 기록 등으로 유출되면 우회 공격이 가능하므로, 원본은 CDN 대역에서만 접근을 허용하도록 방화벽 설정을 함께 해야 한다.)

> 💡 **용어 설명**
>
> - **캐시(Cache)**: 자주 쓰는 데이터를 가까운 곳에 복사해두는 것.
> - **엣지/PoP(Point of Presence)**: CDN 사업자가 각 지역에 세운 서비스 거점. 사용자와 가장 가까운 곳에서 콘텐츠를 응답한다.
> - **DNS/CNAME**: DNS는 도메인 이름(www.univ.ac.kr)을 IP 주소로 바꿔주는 시스템. CNAME은 "이 도메인의 주소는 저 도메인에게 물어보라"는 별칭 등록 방식으로, CDN 연동에 사용된다.

### 4.4 방어 사슬 전체 그림

외부에서 고객 서버까지 트래픽이 지나는 순서:

```
인터넷 → [ISP 클린존] → [CDN 엣지] → 고객 회선 → [방화벽] → [WAF] → 웹서버
          대역폭 공격     분산+캐시                  L3/L4 차단   HTTP 내용
          흡수 (L3/L4)    원본 은닉                  포트 제어    검사 (L7)
```

| 구분 | 계층 | 보는 것 | 잘 막는 것 | 못 막는 것 |
|---|---|---|---|---|
| 클린존 | L3/L4 | 트래픽 총량·패킷 이상 | 대역폭 소진 공격 | 암호화된 L7 공격 |
| CDN | L7(캐시) | 콘텐츠 요청 | 대량 트래픽 분산, 원본 은닉 | 원본 IP 유출 시 우회 공격 |
| 방화벽 | L3/L4 | IP·포트 | 비인가 포트 접근 | 열린 포트로 오는 공격 |
| WAF | L7 | HTTP 내용 | SQL Injection, XSS, L7 DDoS | 회선을 채우는 대용량 공격 |

**핵심: 어느 하나도 다른 것을 대체하지 못한다.** 계층별로 역할이 다른 직렬 보완재다.

## 5. 대역폭 공격을 막는 다른 방법들

클린존(스크러빙)만이 유일한 방법은 아니다. 다만 모든 방법에 공통되는 원칙은 같다 — **대역폭 공격은 병목 지점보다 상류에서만 막을 수 있다.** 방법들의 차이는 "얼마나 상류에서, 무엇을 희생하고 거르느냐"다.

### 5.1 블랙홀링 (RTBH, Remotely Triggered Black Hole)

공격당하는 목적지 IP로 가는 트래픽을 ISP 라우터가 **통째로 버리도록(Null 라우팅)** BGP로 신호를 보내는 방식.

- **장점**: 즉각적이고, ISP 백본과 다른 고객을 확실히 보호하며, 사실상 무료.
- **치명적 단점**: 정상 트래픽까지 전부 버린다. 공격자가 원하던 서비스 중단을 스스로 완성해주는 셈. 표적 서버 하나를 포기하고 나머지 망을 살리는 "손절" 용도다.
- **변형**: 해외발 트래픽만 버리는 선택적 블랙홀링. 이용자가 거의 국내인 서비스(국내 대학 등)에는 꽤 실용적이다.

> 💡 **Null 라우팅**: 라우터에서 특정 목적지행 패킷을 어디로도 보내지 않고 폐기하도록 설정하는 것. "블랙홀(빨려들면 못 나옴)"이라는 이름의 유래.

### 5.2 BGP Flowspec

블랙홀링의 정밀 버전. "목적지 X로 가는 **UDP 123번 포트, 패킷 크기 얼마 이상**만 버려라"처럼 세밀한 필터 규칙 자체를 BGP로 망 전체 라우터에 배포한다.

- **장점**: 증폭 공격처럼 패턴이 명확한 공격은 정상 트래픽 손실 없이 라우터 하드웨어에서 즉시 걸러낸다. 스크러빙 센터로 끌고 올 필요조차 없다.
- **단점**: 규칙으로 표현 가능한 공격에만 유효(정상 트래픽과 같은 포트로 오면 무력). 라우터 장비의 지원 여부·규칙 개수 제한. 잘못된 규칙이 망 전체에 전파되는 운영 리스크.

### 5.3 상류 사업자·클라우드에 맡기기

ISP 자신도 감당 못 할 규모라면 더 상류로 올린다.

- **국제 트랜짓 사업자의 방어 서비스**: 해외 구간에서 미리 걸러서 들여온다.
- **클라우드 스크러빙** (Cloudflare Magic Transit, AWS Shield 등): 고객 IP 대역을 클라우드 사업자가 BGP로 대신 광고해, 전 세계 트래픽이 클라우드의 애니캐스트 망으로 먼저 들어가 정화된 뒤 GRE 터널로 돌아온다. 원리는 ISP 클린존과 동일하되 스크러빙 용량이 수백 Tbps로 압도적. 대신 평시에도 트래픽이 해외 PoP를 경유하며 지연이 생길 수 있다.

> 💡 **트랜짓(Transit)**: 상위 통신사가 하위 통신사·기업에게 "전 세계 인터넷으로 가는 길"을 유료로 제공하는 것. 피어링(상호 교환)과 대비되는 개념.

### 5.4 애니캐스트 (Anycast) 분산

**같은 IP를 전 세계 여러 지점에서 동시에 광고**해서, 트래픽이 발원지에서 가장 가까운 지점으로 각각 흩어지게 만드는 구조적 방법. 미국 봇넷의 공격은 미국 PoP가, 유럽 봇넷은 유럽 PoP가 받으므로 한 곳에 모이지 않는다. 루트 DNS와 대형 CDN이 이 방식으로 버틴다. 단, 서비스 자체가 분산 가능한 형태(DNS, 웹)여야 한다.

> 💡 **애니캐스트(Anycast)**: 동일한 IP 주소를 여러 서버가 공유하고, 라우팅이 사용자를 가장 가까운 서버로 자동 연결하는 방식. 유니캐스트(1:1)와 대비된다.

### 5.5 회선 증설 (Over-provisioning)

공격보다 파이프를 크게 만드는 원시적 방법. 10G 공격은 100G 회선이면 그냥 지나간다. 대형 포털·게임사는 실제로 상시 여유 대역폭을 공격 흡수 버퍼로 쓴다. 다만 Tbps급 공격 시대에 비용 대비 한계가 명확해, 단독 대책이 아니라 다른 방법의 시간을 벌어주는 보조 수단이다.

### 5.6 발원지 차단 — BCP38 (uRPF, Ingress Filtering)

방향이 다른 예방적 접근. 증폭·반사 공격은 출발지 IP 위조가 전제인데, **모든 ISP가 자기 가입자 구간에서 "자기 대역이 아닌 출발지 IP를 단 패킷"을 나가지 못하게 막으면** 위조 기반 공격 자체가 성립하지 않는다. 인터넷 표준 권고(BCP38)로 오래전부터 존재하지만, 이득이 남의 망에 돌아가는 구조라 전 세계 시행률이 낮다. ISP 입장에서는 "우리가 공격 발원지가 되지 않게 하는" 위생 조치다.

> 💡 **uRPF(unicast Reverse Path Forwarding)**: 라우터가 패킷의 출발지 IP를 보고 "이 IP가 이 방향에서 들어오는 게 맞나"를 역검사해, 위조된 출발지의 패킷을 버리는 기능.

### 5.7 방법별 비교 정리

| 방법 | 정상 트래픽 보존 | 대응 규모 | 핵심 한계 |
|---|---|---|---|
| 블랙홀링(RTBH) | ✗ (전부 폐기) | 무제한 | 서비스 중단을 스스로 완성 |
| Flowspec | ○ | 라우터 성능만큼 | 패턴 명확한 공격만 |
| 스크러빙(클린존) | ○ | 센터 용량만큼 | 구축·운영 비용 |
| 클라우드 스크러빙 | ○ | 수백 Tbps | 평시 경유 지연, 해외 사업자 계약 |
| 애니캐스트 | ○ | 분산 지점 수만큼 | 분산 가능한 서비스만 |
| 회선 증설 | ○ | 비용만큼 | 근본 해결 아님 |
| BCP38 | — (예방) | 예방적 | 모두가 해야 효과 |

실제 ISP 운영은 이를 단계적으로 조합한다: 평시엔 Flowspec으로 명백한 쓰레기 트래픽(증폭 공격 포트)을 라우터에서 걸러내고 → 공격 탐지 시 해당 대역만 클린존으로 우회시키고 → 클린존 용량을 넘는 초대형이면 선택적 블랙홀링·상류 차단으로 손절한다.

클린존이 "유일한 방법"이라 상품이 된 것이 아니라, **정상 트래픽을 살리면서 막는 방법 중 ISP가 고객에게 서비스 형태로 제공할 수 있는 것**이 스크러빙이기 때문이다. 블랙홀링은 무료지만 서비스가 죽고, 클라우드 스크러빙은 강력하지만 고객이 직접 해외 사업자와 계약해야 한다. 그 사이가 ISP 클린존의 자리다.

---

## 6. 영업 실무 관점 정리 (B2B 담당자용)

고객(대학 전산팀 등) 질의 대응의 뼈대가 되는 세 문장:

1. **클린존은 "고객 회선 상단에서 대역폭 공격을 흡수하는 망 차원의 방어"다.** 고객이 어떤 보안 장비를 갖고 있어도, 회선이 차기 전에 막아줄 수 있는 것은 ISP뿐이다.
2. **설치 국사는 물리적 거점일 뿐, BGP 라우팅으로 망 전체 유입점을 커버한다.** "다른 경로로 들어오는 공격은요?"라는 질문에 대한 답이다.
3. **암호화된 L7 공격은 고객단 WAF/CDN과 역할을 나눠 막는 구조다.** 클린존을 만능으로 팔았다가 L7 공격이 뚫리면 신뢰 문제가 되고, 이 구분을 정확히 설명하면 오히려 전문성으로 보인다.

추가 포인트:

- **혼합 공격이 표준**: 실제 대형 공격은 대역폭 공격으로 시선을 끌고 L7으로 실제 타격하는 식으로 유형을 섞는다. 따라서 "계층별 방어 조합"이 표준 답안이다.
- **대학 고객 특수성**: 대학은 공격 표적이 되기도 하지만, 학생 PC 감염으로 **공격 발원지**가 되는 경우도 많다. 방어뿐 아니라 발신 트래픽 이상 탐지 관점에서도 대화가 가능하다.
- **수강신청 시나리오 구분**: 특정 시점에 정상 트래픽이 폭주하는 것(수강신청)은 DDoS가 아니라 용량 설계·L7 처리 문제다. 클린존이 아니라 WAF/CDN/서버 증설 영역이라고 선을 그어주는 것이 정확한 컨설팅이다.

## 부록. 핵심 용어 한눈에 보기

| 용어 | 의미 |
|---|---|
| DDoS | 다수의 봇을 동원해 자원을 고갈시켜 서비스를 마비시키는 공격 |
| 봇넷(Botnet) | 공격자가 원격 조종하는 감염 PC/서버들의 군단 |
| IP 스푸핑 | 패킷 출발지 IP를 위조하는 것 |
| 증폭 공격 | 열린 DNS/NTP 서버를 악용해 작은 요청으로 큰 응답을 피해자에게 쏘게 하는 공격 |
| SYN Flood | TCP 연결 절차를 절반만 하고 방치해 세션 테이블을 고갈시키는 공격 |
| L3/L4/L7 | OSI 계층 — IP(L3), 포트(L4), 애플리케이션 내용(L7) |
| 클린존/스크러빙 센터 | ISP 백본의 대형 트래픽 정화 시설 |
| NetFlow/sFlow | 라우터의 트래픽 통계 요약·전송 기능 (탐지에 사용) |
| BGP | 인터넷의 경로 광고·길찾기 프로토콜 |
| More-specific 광고 | 더 좁은 대역을 광고해 트래픽을 끌어오는 BGP 기법 (클린존 유인 원리) |
| GRE 터널 | 패킷 캡슐화로 만드는 논리적 전용 통로 (정화 트래픽 반환에 사용) |
| IX | ISP들이 트래픽을 교환하는 접속점 |
| 피어링 | ISP 간 상호 트래픽 직접 교환 |
| 국사 | 통신 장비가 설치된 통신사의 물리적 거점 시설 |
| 백본 | 통신사 네트워크의 중심 기간망 |
| 방화벽 | IP·포트 기준(L3/L4)으로 통과/차단하는 기본 보안 장비 |
| Stateful | 연결 상태를 기억하며 동작하는 방식 |
| WAF | HTTP 내용을 검사(L7)하는 웹 전용 보안 장비 |
| SQL Injection / XSS | 웹 입력값에 DB 명령/악성 스크립트를 끼워 넣는 대표적 웹 공격 |
| CDN | 콘텐츠를 전 세계 엣지에 분산 캐시하는 인프라 (부수 효과로 DDoS 방어) |
| 엣지/PoP | CDN·통신사의 지역 서비스 거점 |
| RTBH(블랙홀링) | 피해 IP행 트래픽을 통째로 폐기하는 대응 |
| BGP Flowspec | 세밀한 필터 규칙을 BGP로 망 전체에 배포하는 기술 |
| 애니캐스트 | 같은 IP를 여러 지점에서 광고해 트래픽을 자연 분산시키는 방식 |
| BCP38/uRPF | 출발지 IP 위조 패킷을 발원지에서 차단하는 예방 표준 |
