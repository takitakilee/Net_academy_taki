# [기술 개념] BGP (Border Gateway Protocol)

---

## 문서 요약 (Summary)

**BGP (Border Gateway Protocol)** 는 인터넷상의 서로 다른 자율 시스템 (Autonomous System, AS) 간에 라우팅 정보를 교환하는 핵심 라우팅 프로토콜입니다. 유선통신사 환경에서는 타 통신사·고객사(대학교, 기업 등)와의 망 연동 및 다중 회선 트래픽 경로 제어의 표준 수단으로 사용됩니다.

---

## 핵심 개념 (Key Concepts)

- **자율 시스템 (Autonomous System, AS)**
  - 인터넷은 독립적으로 관리되는 수천 개의 네트워크(AS)로 구성됩니다.
  - 각 AS는 고유의 **AS 번호 (Autonomous System Number, ASN)** 로 식별됩니다.

- **경로 벡터 기반 라우팅 정보 교환**
  - BGP는 AS 간 라우팅 정보를 교환하여 데이터가 목적지까지 **최적 경로**로 전달되도록 경로를 선택·공유합니다.
  - 단순 최단 경로가 아닌 **정책(Policy), 비용, 지연 시간** 등 다양한 조건을 종합해 경로를 결정합니다.

- **BGP 피어링 (Peering)**
  - **TCP 포트 179**를 이용해 인접 라우터(BGP 피어)와 세션을 맺고 라우팅 정보를 주고받습니다.

- **라우팅 정책 (Routing Policy) 구현**
  - 각 AS는 자체 정책에 따라 경로를 선택하거나 필터링할 수 있어, 트래픽을 능동적으로 제어할 수 있습니다.
  - 대표 설정 도구: `route-map`, `filter-list`, `prefix-list` 등

- **안정성 및 다중 경로 지원**
  - 장애 발생 시 신속한 경로 재설정(Convergence)으로 네트워크 연속성을 유지합니다.
  - 다중 경로를 통한 **트래픽 부하 분산 (Load Balancing)** 을 지원합니다.

## 구성 및 동작 원리 (Architecture & Mechanism)

### 1. 기본 동작 흐름

1. **세션 수립**: BGP 라우터가 TCP 포트 179로 피어와 연결을 맺음
2. **라우팅 정보 교환**: 각 AS가 보유한 경로 정보(NLRI)를 UPDATE 메시지로 광고
3. **경로 선택**: 정책·속성(AS-Path, Local Preference 등)을 기준으로 최적 경로 결정
4. **장애 대응**: 피어 다운 또는 경로 소실 감지 시 대체 경로로 재수렴

### 2. BGP가 필요한 이유

| 필요성 | 설명 |
|---|---|
| **AS 간 라우팅 정보 교환** | 수천 개 AS 간 라우팅 정보를 효율적으로 교환해 목적지 도달성 보장 |
| **최적 경로 선택** | 최단 경로뿐 아니라 정책·비용·지연 시간을 고려한 경로 결정 |
| **안정성·접근성 보장** | 장애 시 신속한 경로 재설정으로 서비스 연속성 유지 |
| **네트워크 정책 구현** | AS별 자체 정책 기반 경로 선택·필터링으로 트래픽 관리 |
| **다중 경로·부하 분산** | 복수 경로로 트래픽을 분산해 효율성과 안정성 향상 |

### 3. 연동에 필요한 장비

- BGP는 **라우터** 또는 **L3 스위치**에서 구현합니다.
- 고객사(대학교·기업)는 통상 **코어 L3 스위치 또는 라우터**에 BGP 기능이 탑재되어 있어야 합니다.
- 장비 선정 기준: **BGP 세션 안정성, 라우팅 테이블 처리 성능(Full Table 수용 여부), 보안성**

## 실무 적용 사례 (Use Case)

### 1. 통신사 간 망 연동 (Inter-AS Peering)

- 각 통신사(예: KT, SK브로드밴드, LG U+)는 자체 ASN을 보유하며, 서로 다른 네트워크·라우팅·보안 정책을 운영합니다.
- BGP를 통해 통신사 네트워크와 고객 네트워크(대학교, 기업 등)가 연동될 때, 상호 정책을 존중하며 안정적인 경로를 형성합니다.
- 통신사별 라우팅 설정(`route-map`, `filter-list` 등)이 상이하므로, 연동 시 **정책 협의 및 설정 최적화** 작업이 필수입니다.

### 2. 고객사 다중 회선(Multi-homing) 구성

고객사가 복수 통신사 회선을 사용하는 이유와 BGP의 역할:

- **이중화 및 안정성 확보**: 한 통신사 회선 장애 시에도 타 통신사 경유로 인터넷 접속 유지
- **트래픽 부하 분산**: 복수 회선으로 트래픽을 분산해 효율 향상 및 지연 시간 감소
- **비용·서비스 다양성**: 통신사별 품질·비용·대역폭 차이를 활용한 최적 서비스 구성
- BGP는 이러한 **다중 통신사 회선의 경로 제어와 관리**에 필수적입니다.

### 3. 구축 사례

> **부산 OO대학교**: 코어엣지 네트웍스 **C5000 L3 스위치**를 코어 장비로 사용하여 KT와 BGP 연동을 구축. 다중 회선 환경에서 BGP 기반 경로 제어로 이중화 및 부하 분산을 구현.

## 주의사항 및 FAQ

### 주의사항

- **정책 불일치 주의**: 통신사별 라우팅 정책이 다르므로, 연동 전 반드시 상대 AS와 광고/수신 프리픽스 범위와 필터 정책을 협의해야 합니다.
- **장비 성능 확인**: Full Routing Table 수신 시 라우팅 테이블 규모가 크므로, 장비의 메모리·처리 성능을 사전에 검증해야 합니다.
- **세션 안정성 관리**: BGP 세션 플랩(Flap)은 대규모 경로 재수렴을 유발하므로, 회선 품질과 피어 상태를 상시 모니터링해야 합니다.

### FAQ

- **Q. BGP는 사내망(내부 라우팅)에도 쓰나요?**
  - A. AS 내부 라우팅은 주로 IGP(OSPF 등)를 사용하고, BGP는 AS 간(eBGP) 또는 대규모 내부 경로 전달(iBGP)에 사용합니다.

- **Q. 고객사가 BGP 연동을 하려면 무엇이 필요한가요?**
  - A. 자체 ASN, BGP 지원 라우터 또는 코어 L3 스위치, 그리고 통신사와의 피어링 정책 협의가 필요합니다.

- **Q. 왜 단일 통신사 회선으로는 부족한가요?**
  - A. 단일 회선은 해당 통신사 장애 시 인터넷 접속이 전면 중단됩니다. 다중 회선 + BGP 구성이 이중화와 부하 분산을 보장합니다.
